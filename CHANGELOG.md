## [0.4.0-alpha] — 2026-10-29

### Добавлено

- Сквозные счётчики: двойной клик по имени в окне «Счётчики» переименовывает счётчик вместе с полями проектов; занятое имя показано в окне полей недоступным
- Сквозные счётчики (026): создаются в окне 1 кнопкой «Счётчики...», общие для всех проектов, хранятся в `settings.json`; поле шаблона типа «счётчик» может ссылаться на них. Значение меняется в том же окне; при генерации документы нумеруются от него, позиция сохраняется
- Настройки проекта: разделы «Данные», «Шаблоны» и «Результаты» с путём до папки каждого; кнопка «+» у «Результаты» добавляет папку для копий результата (подсказка при наведении), «×» убирает её из списка
- Поле конфига `result_dirs`: абсолютные пути папок, в которые копируется каждый результат; относительные пути отклоняются
- Окно 2: кнопка «Убрать» у каждого источника; источник отвязывается вместе со своими счётчиками, файл остаётся в «Данные». Нельзя убрать последний источник или источник, чьи счётчики нужны полям шаблонов
- Окно 1: кнопка «Редактировать» у проекта между «Сгенерировать» и «Убрать» открывает окно проекта, как клик по имени

### Изменено

- Лимит шаблона определяет число документов: `0` — не создавать ни одного, больше `0` — создавать. Счётчики на `0` больше не блокируют генерацию: прогон начинается с первой строки. Прежнее значение `0` как «без лимита» отменено; новые шаблоны получают лимит `0` и ничего не создают, пока лимит не задан

### Исправлено

- Счётчики проекта удаляются кнопкой «Убрать» в окне полей. Удаление доступно, если ни одно поле его не читает; счётчик источника уходит вместе с источником
- Сохранение поля со сквозным счётчиком не копирует его имя в счётчики проекта; проекты, где такая копия уже есть, нужно переименовать сквозной счётчик в окне «Счётчики»
- Счётчик источника не получает имя сквозного счётчика (`v_num` → `v_num_2`); раньше при генерации выходила ошибка «есть и в проекте, и среди сквозных»
- Генерация с лимитом больше `0` и счётчиком на `0` создаёт документы; раньше их не было
- `.stanok` и `settings.json` пишут версию приложения; раньше записывалось `0.0.0`
- Открытие `.stanok` старой версии: валидный файл получает текущую версию и перезаписывается (резервная копия `.bak` при этом сохраняется); файл новее программы даёт ошибку без восстановления из `.bak`; неподходящий старый файл восстанавливается из `.tmp`/`.bak`, а при неудаче показывает причину

## [0.3.0-alpha] — 2026-10-28

### Добавлено

- Создание проекта в три шага (024): окно «Создать проект» с кнопками «Создать минимальный шаблон», «Выбрать готовую папку» и «Создать из существующего проекта»; проверка структуры с перечнем ошибок и предупреждений по файлам и колонкам; копия структуры и шаблонов существующего проекта
- Диалог открытия: «Выбрать папку» проверяет структуру тем же окном и предлагает создать недостающие подпапки `Данные` и `Шаблоны`
- Диалог необработанной ошибки просит связаться с разработчиком и приложить файл лога
- Логирование: старт/конец каждой сессии с версией `stanok`, версией PJ, режимом GUI/CLI, PID, домашней папкой и кодом выхода; глобальные хуки `sys.excepthook`, `threading.excepthook` и `qInstallMessageHandler`; необработанные ошибки пишутся как `CRITICAL` с traceback и показываются в диалоге, не закрывая GUI
- Логирование генерации: фактический шаблон и файл, лимит, режимы и стартовые позиции счётчиков, строки по источникам, неучаствующие источники, `planned`, `resolved`, `created`, `errors`, `skipped_limit`, `skipped_exhausted`, путь результата и созданные документы
- `GenerateReport`: поля `resolved`, `skipped_limit`, `skipped_exhausted`, `output_dir`; `engine.resolve.available_documents` считает доступные строки без учёта лимита
- Аудит исключений: ожидаемые ошибки ловятся конкретными типами, неожиданные — `CRITICAL` с `exc_info`; логи переведены на f-строки

### Исправлено

- Недавние проекты: порядок сохраняется при добавлении, удалении и смене настроек; лимит 10 отбрасывает самый старый проект, а не самый новый
- Недавние проекты обновляются после импорта, даже если диалог открытия закрыт без выбора
- Подсказка папки при создании проекта берётся из последнего открытого проекта
- Подписи формата даты в окне полей показывают текущую дату
- Удаление проекта с папкой: если в папке есть чужие файлы или папки, удаляются только `Данные`, `Шаблоны` и `Результат`
- Имя результата с точками сохраняется (`Договор №1.2` → `Договор №1.2.docx`)
- Окна 2 и 3: высота строк таблиц подстраивается под содержимое, длинные названия шаблонов и путей переносятся на несколько строк
- Окно 3: изменение счётчика больше не падает при наличии константных или date-полей; ошибки изменения счётчиков логируются как `CRITICAL` и показываются пользователю, окно остаётся открытым
- Окно 3: кнопка «Создать счётчик» снова создаёт счётчик (лишний аргумент `clicked` больше не передаётся в обработчик)
- Сохранение PJ: основной `.stanok` больше не исчезает между созданием `.bak` и заменой; резервная копия делается копированием, а основной файл заменяется атомарно
- Окно 3: выбор значения из таблицы работает в собранном exe и для источника «Одна строка» — модуль выбора включается в сборку статическим импортом
- Окно 3: над таблицей счётчиков добавлено развёрнутое описание счётчика — назначение, создание и сдвиг при генерации

## [0.2.0-alpha] — 2026-10-20

- Интерфейс: единая светлая тема (`gui.theme`) — типографика Segoe UI, заголовки и подзаголовки, карточные таблицы, скруглённые поля и кнопки, акцентная primary-кнопка, тонкие скроллбары; обновлены окна 1–4, настройки и выбор значения; длинные пути сокращаются с многоточием
- Окно «Открыть проект»: кнопка «Выбрать папку» — рекурсивно переносит найденные `.stanok` в Home, восстанавливает путь проекта по папке, добавляет валидные проекты в recent и показывает количество; папка с `Данные/Шаблоны/Результат` открывает окно создания с именем, базовой папкой и файлами, остальные папки — предупреждение
- `ProjectStore.import_configs`: импорт конфигов с уникальными именами, пропуском файлов внутри Home, отчётом об ошибках и отсутствующих папках; `init_project` не создаёт копию файла, уже лежащего в целевой подпапке (`data (1).xlsx`)
- `ProjectStore.delete_project`: при удалении с папкой сначала удаляется папка, затем конфиг — ошибка `rmtree` (занятый файл) больше не оставляет проект без конфига; `init_project` отказывает, если имя занято даже одним `.bak`
- `tables`: пустые заголовки в середине таблицы больше не блокируют чтение — такие столбцы пропускаются, а окно полей и итог генерации показывают их буквы; дубли и полностью пустая строка заголовков по-прежнему ошибка
- `ProjectStore`: UTF-8 BOM после внешнего редактирования снимается и файл атомарно перезаписывается без BOM; если снять не удалось, конфиг восстанавливается из `.tmp`/`.bak`
- `ProjectStore`: битый или пропавший `<имя>.stanok` восстанавливается из валидного `<имя>.stanok.tmp` (незавершённая запись), иначе из `<имя>.stanok.bak`; основной файл перезаписывается, `.bak` сохраняется; если оба невалидны — обычная ошибка загрузки. `delete` удаляет и `.tmp`
- Окно 1: перед кнопкой «Сгенерировать» в строке проекта показаны имя шаблона по умолчанию и его лимит; лимит редактируется на месте и сразу сохраняется в PJ
- Окно 2: колонки шаблонов в порядке «Шаблон | По умолчанию | Лимит | Сгенерировать | Редактировать | Убрать»; вместо клика по названию — кнопка «Редактировать»; под таблицей источников добавлено пояснение типов; после создания проекта типы источников и кнопки «Редактировать» плавно мигают зелёным до первого действия
- Счётчики (021): `last` и `start_row` объединены в одну позицию `CounterDef.pos` — это и строка источника, и печатаемое число; номер читается `format`-ом как `pos` без добавления единицы (первый документ печатает `pos`); `constant` не меняет позицию, circular хранит абсолютный счёт; в окне 3 одна колонка «Позиция» с кнопкой-глазом, её изменение обновляет предпросмотр и counter-, и table-полей; legacy `last`/`start_row` сводятся в `pos` при загрузке

- Окно 3 (021): таблица счётчиков (источник, позиция, «начинать заново», текущее, ширина), table-поле выбирает счётчик + колонку, counter-поле — счётчик с предпросмотром; сохранение валидирует PJ

- `services.generate`: dist без расширения сохраняется как `.docx`

### Исправлено

- Окно 2: при мигании типа источника фон выпадающего списка остаётся белым; мигание этой ячейки прекращается при открытии списка
- Окно 2: при перетаскивании границы столбца таблицы шаблонов ширину меняет именно этот столбец; убрана авто-растяжка первого столбца (`Stretch`), которая одновременно сдвигала соседнюю границу
- Диалоги: кнопки подтверждения переведены на русский — `Да/Нет`, `Сохранить/Не сохранять/Отмена`, `ОК/Отмена` (удаление проекта и шаблона, переезд папки, создание папки, несохранённые изменения, имя счётчика, выбор таблицы); при старте подключается Qt-перевод `qtbase_ru` для остальных стандартных строк
- Итог генерации поясняет нехватку строк: при `limit` больше доступных строк сообщение показывает «создано N из LIMIT (строки закончились)»; лимит остаётся верхней границей, sequential по-прежнему останавливается на конце таблицы
- Окно выбора значения (вариант 1): строка выбирается целиком, в «Номер» записывается её 0-базовый номер (колонка «Строка»); двойной клик подтверждает выбор; под таблицей показано «Будет записано: N». Автоподстановки текущего значения нет — «Выбрать» активна только после явного выбора строки
- Окно 3 (021): чекбокс «Начинать заново» приведён в соответствие семантике `resume` (отметка = сброс позиции, `resume=0`); раньше был инвертирован
- `engine.schema` (021): counter-поле (`source=counter`) валидируется — значение обязано ссылаться на существующий счётчик (`PJValidationError` при загрузке)
- `engine.resolve` (021): `participating_sources` не падает `KeyError` на «висячей» ссылке counter-поля — защитно пропускает, ошибку отдаёт `resolve_rows` чистым `ResolveError`
- `services.generate` (021): счётчики и курсоры персистятся при любом обработанном документе (`processed > 0`), включая прогон, где все документы завершились ошибкой
- Окно 2 (021): лимит шаблона сохраняется сразу при изменении спинбокса (раньше терялся при закрытии окна без прогона)
- Окно создания/настроек проекта: виджеты другого режима больше не видны (в режиме создания пропал пустой список «Шаблон по умолчанию», перекрывавший подпись «Имя проекта»; в режиме настроек — пустые таблицы файлов)
- Окно 2 → «Настройки»: открытие окна настроек больше не падает с `TypeError` (путь папки передаётся строкой)

## [0.1.0] — 2026-10-15

### Добавлено
- `tables`: чтение Excel (`ExcelReader`, протокол `TableReader`, `TableReadError`); валидация заголовков, нормировка строк
- `engine.schema`: модели PJ/AJ/Filling на pydantic v2, `validate_*`, `normalize`, реестр `MIGRATIONS` + `migrate()`, `FormatTooNewError`
- `engine.resolve`: строки + PJ → Filling JSON; режимы sequential/circular/constant; счётчики plain/month; `dist` из filename_template (чистая функция, без мутации PJ)
- `engine.render` + `xmlops`: Filling → docx; run-merge с сохранением форматирования, `\n` → разрывы, таблицы (включая вложенные); строгий режим (неизвестное поле → `RenderError`)

- `services.generate`: `generate_documents(cmd)` — пайплайн tables → resolve → render → `Результат/`; `GenerateCommand`/`GenerateReport`; счётчики `last += created`, resume, `max_docs`, уникальные имена `(1)`, построчные ошибки в отчёт; CLI `python run.py <проект>`
- `gui.strings`: `STRINGS` — единый модуль пользовательских строк (NFR-3); AST-тест запрещает кириллические литералы в `src/` вне него
- `gui.main_window` + `worker`: окно 1 (recent-список, запуск по каждому/все последовательно со сводкой, настройки-заглушка, обзор); прогон в QThread, прогресс/отмена; `progress`-колбэк в `generate_documents`; `run.py` без аргументов открывает окно; PyQt5-зависимость
- `gui.project_dialog`: окно 2 (шапка проекта, таблица шаблонов с кол-вом, прогон по шаблону, хук окна 3); окно 1 открывает настоящий диалог (заглушка убрана)

- `app.create_gui`: общий `ProjectStore`, bootstrap без `exec_`; сквозной GUI-тест 1→2→3→docx; CLI-регрессия в тестах
