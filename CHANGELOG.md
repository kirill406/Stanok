## [Unreleased]

- Счётчики (021): счётчик владеет источником — `CounterDef.table/start_row/resume`, счётчик можно привязать к любому источнику; `FieldDef.counter_name` (table-поле выбирает счётчик, не файл); `TemplateDef.limit` (лимит шаблона); `ProjectJSON.default_template` (шаблон по умолчанию с валидацией); генерация собирает один документ из всех задействованных источников сразу (режимы на источник), курсор вперёд на `created+errors`, `resume` управляет переносом позиции, авто-создание счётчиков при добавлении источника/создании проекта
- Окно 2 (021): таблица источников (файл + режим), таблица шаблонов (лимит, radio «по умолчанию», прогон, удаление; удаление шаблона по умолчанию запрещено), кнопки «Добавить шаблон/источник» и «Настройки»; окно 4 объединено с настройками проекта (имя ro, папка, шаблон по умолчанию)
- Окно 3 (021): таблица счётчиков (источник, позиция, «начинать заново», текущее, ширина), table-поле выбирает счётчик + колонку, counter-поле — счётчик с предпросмотром; сохранение валидирует PJ
- Окно 3 (020): смена источника поля (тип-комбобокс, файл+колонка для table с value-лейблом, имя+ширина для счётчика, форматы даты с русской локалью); `FieldDef.table`, ширина счётчика вместо plain/month (legacy рендерится); окно 2 синхронизирует новые плейсхолдеры docx в PJ при открытии
- `services.generate`: dist без расширения сохраняется как `.docx`
- Идентичность проекта по имени конфига: `ProjectJSON.folder` (абсолютный путь папки), `project_folder` берёт папку из PJ, `resolve_project` самолечит/резолвит по recent; окно 1 хранит config в recent-строках, «Открыть проект» — список проектов, пропавшая папка → «указать новую» (`set_project_folder`); окно 4 — предпросмотр пути, confirm создания папки, блок занятого имени и `Данные/`/`Шаблоны`
- Окно 3 (020): текущее значение счётчика правится только в таблице счётчиков; в строке поля-счётчика колонка «Значение» — нередактируемый предпросмотр
- Окно создания проекта: «Папка» — базовая, проект создаётся в `<папка>\<имя>` (`Данные/`, `Шаблоны/`, `Результат/`); предпросмотр «Файлы проекта» показывает абсолютный путь проекта и три подпапки отдельными строками (в т.ч. в настройках проекта, где база — сама папка проекта); если папки проекта нет — вопрос «Создать?» (отказ → возврат к редактированию); `init_project` создаёт и `Результат/`
- Окно 3: колонки таблицы счётчиков подгоняются по ширине текста (заголовки и значения видны целиком)
- Окно 3: в таблице счётчиков колонка «Ширина» переименована в «Формат» и перенесена сразу за «Источник данных»; «Начинать заново» — в конец
- Окно 3: «Позиция» → «Начальная строка», «Текущее значение» → «Номер (значение)», «Источник» → «Источник данных»; добавлены подсказки к колонкам и полям, под таблицей — пояснение
- Окно 3 (021): пропавший файл источника — однократное предложение «Выбрать папку с источником» (файл находится по имени и копируется в проект или привязывается относительным путём) либо «Создать папку» (`Данные`/`Шаблоны`); далее — обычное предупреждение (один раз на источник)
- Окно 3: источник «Одна строка» — «Начальная строка» только для чтения; изменение «Номер (значение)» сразу обновляет предпросмотр counter-полей в таблице полей; рядом с «Номер» — кнопка-глаз «Выбрать данные» и общий каркас выбора значения из привязанной таблицы (конкретные варианты — в отдельных ветках)
- Окно 3: вариант 1 выбора значения — вся таблица сеткой (0-базовый номер строки + колонки), выбор числовой ячейки, двойной клик подтверждает; текущее значение подсвечивается

### Исправлено

- Окно выбора значения (вариант 1): убрана автоподстановка текущего значения — раньше «Выбрать» была активна сразу, и при клике по строке/заголовку записывалось старое значение; теперь выбирается только явно нажатая числовая ячейка, под таблицей показано «Будет записано: N», колонка «Строка» не выбирается
- Окно 3 (021): чекбокс «Начинать заново» приведён в соответствие семантике `resume` (отметка = сброс позиции, `resume=0`); раньше был инвертирован
- `engine.schema` (021): counter-поле (`source=counter`) валидируется — значение обязано ссылаться на существующий счётчик (`PJValidationError` при загрузке)
- `engine.resolve` (021): `participating_sources` не падает `KeyError` на «висячей» ссылке counter-поля — защитно пропускает, ошибку отдаёт `resolve_rows` чистым `ResolveError`
- `services.generate` (021): счётчики и курсоры персистятся при любом обработанном документе (`processed > 0`), включая прогон, где все документы завершились ошибкой
- Окно 2 (021): лимит шаблона сохраняется сразу при изменении спинбокса (раньше терялся при закрытии окна без прогона)
- Окно создания/настроек проекта: виджеты другого режима больше не видны (в режиме создания пропал пустой список «Шаблон по умолчанию», перекрывавший подпись «Имя проекта»; в режиме настроек — пустые таблицы файлов)
- Окно 2 → «Настройки»: открытие окна настроек больше не падает с `TypeError` (путь папки передаётся строкой)

## [0.1.0] — 2026-10-15

### Добавлено
- `tables`: чтение Excel (`ExcelReader`, протокол `TableReader`, `TableReadError`); валидация заголовков, нормировка строк
- `engine.schema`: модели PJ/AJ/Filling на pydantic v2, `validate_*`, `normalize`, реестр `MIGRATIONS` + `migrate()`, `FormatTooNewError`
- `engine.resolve`: строки + PJ → Filling JSON; режимы sequential/circular/constant; счётчики plain/month; `dist` из filename_template (чистая функция, без мутации PJ)
- `engine.render` + `xmlops`: Filling → docx; run-merge с сохранением форматирования, `\n` → разрывы, таблицы (включая вложенные); строгий режим (неизвестное поле → `RenderError`)
- `services.storage`: `ProjectStore` (атомарная запись tmp+fsync+rename+`.bak`, миграция в Home, recent ≤ 10 с дедупом, защита путей)
- `services.generate`: `generate_documents(cmd)` — пайплайн tables → resolve → render → `Результат/`; `GenerateCommand`/`GenerateReport`; счётчики `last += created`, resume, `max_docs`, уникальные имена `(1)`, построчные ошибки в отчёт; CLI `python run.py <проект>`
- `gui.strings`: `STRINGS` — единый модуль пользовательских строк (NFR-3); AST-тест запрещает кириллические литералы в `src/` вне него
- `gui.main_window` + `worker`: окно 1 (recent-список, запуск по каждому/все последовательно со сводкой, настройки-заглушка, обзор); прогон в QThread, прогресс/отмена; `progress`-колбэк в `generate_documents`; `run.py` без аргументов открывает окно; PyQt5-зависимость
- `gui.project_dialog`: окно 2 (шапка проекта, таблица шаблонов с кол-вом, прогон по шаблону, хук окна 3); окно 1 открывает настоящий диалог (заглушка убрана)
- `gui.fields_dialog`: окно 3 (правка констант, превью table/counter/today, Save в PJ, dirty-чек Save/Discard/Cancel); окно 2 открывает настоящий диалог
- `app.create_gui`: общий `ProjectStore`, bootstrap без `exec_`; сквозной GUI-тест 1→2→3→docx; CLI-регрессия в тестах
- `engine.resolve` + `services.generate` (012): `limit` в `resolve_rows` (честный circular/constant), курсор по режимам, `resumed_from` в отчёте
- `services.generate` + GUI (013): прогон по всем Excel-источникам (FR-7), сквозные счётчики, курсоры на источник, `--source` в CLI, комбобокс источников в окне 2
- `services.storage` + GUI (014): `init_project` — создание проекта (FR-12), копирование в `Данные/`/`Шаблоны/` с уникализацией, PJ из плейсхолдеров docx, окно 4 из окна 1
- `services.storage` + окно 2 (015): `add/remove_template`, `delete_project`, `remove_recent` (FR-13); кнопки шаблонов и снос проекта с confirm
- GUI (016): FR-10 — окно 3 и reload окна 2 при битых входах показывают диалог, окна живы
- Окно 1 + `services.storage` (017): FR-14 — дружелюбная ошибка пустой папки; миграция с коллизией уходит в `имя (N)`
- `app` + окно настроек (018): `stanok.log` с ротацией в Home, уровень из AJ, `STANOK_HOME`, окно настроек вместо стаба
- Тесты: `tests/tables/`, `tests/engine/test_schema.py`, `tests/engine/test_resolve.py` (покрытие движка ~99%)
