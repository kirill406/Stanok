# Станок — Генератор документов из шаблонов

Десктопное приложение для автоматического заполнения .docx-шаблонов данными из Excel.

## Установка

### Быстрый запуск (готовый .exe)

Скачай Станок.exe из релизов, запусти двойным кликом. Никаких установок.

### Запуск из исходников (для разработчиков)

`powershell
# 1. Клонируй репозиторий
git clone <repo-url>
cd FirstAgent

# 2. Установи Python 3.8+, uv и зависимости
uv sync

# 3. Запусти GUI
python run.py
`

### Сборка .exe

`powershell
pip install pyinstaller
pyinstaller Станок.spec
`

Результат: dist/Станок.exe — один файл, работает без Python.

> ⚠️ Собирай только через `Станок.spec` — в нём прописаны `src/` (`pathex`),
> иконки и данные. Голый `pyinstaller run.py` даст нерабочий .exe
> (`ModuleNotFoundError: No module named 'docxforge'`) и затрёт спеку.

## Быстрый старт

### 1. Создай проект

Запусти Станок → «Создать новый проект» → выбери папку.

Получится структура:
`
МойПроект/
├── Данные/          ← сюда скопируй .xlsx файлы
├── Шаблоны/         ← сюда скопируй .docx шаблоны
└── проект.docxforge  ← файл настроек (автоматический)
`

### 2. Подготовь шаблон

В Word вставь пометки {{ имя_поля }} в места, куда нужно подставлять данные:

`
Договор поставки № {{ doc_number }}
от {{ today:dd.MM.yyyy }}

{{ организация }}, в лице {{ фио_поставщика }},
и {{ название_клиента }}, в лице {{ фио_клиента }}.

ИНН: {{ ИНН_клиента }}
`

Специальные поля (подставляются автоматически):
- {{ today }} — текущая дата
- {{ today:dd.MM.yyyy }} — дата с форматом
- {{ doc_number }} — порядковый номер
- {{ doc_number:0001 }} — номер с ведущими нулями
- {{ image:имя }} — изображение

### 3. Настрой поля

Выбери шаблон → «Заполнить» → для каждого поля выбери тип источника:

- **Константа** — одно значение на все документы
- **Таблица** — значение из Excel (файл → столбец → строка)
- **Счётчик** — автоинкремент
- **Изображение** — картинка (логотип, подпись)

### 4. Генерация

- **«Один документ»** — один заполненный .docx (по умолчанию)
- **«Несколько — по строкам таблицы»** — пакетная генерация с настройкой для каждого источника:
  - *Константная строка* — один документ из первой строки
  - *По строкам до конца* — итерация по всем строкам
  - *До заданного числа* — первые N строк
  - *По кругу* — циклическое повторение строк
- **«Ограничить общее количество документов»** — лимит на общее число файлов

## Тестирование

### Быстрая проверка движка

`powershell
python tests/smoke_engine.py
`

Создаёт тестовый проект tests/test_project/, генерирует договор, проверяет все поля.

### Автоматические тесты (pytest)

Проект содержит **97 тестов**, покрывающих весь движок (engine).

`powershell
# Установить зависимости для тестирования
uv sync

# Запустить все тесты
uv run pytest tests/ -v

# Тихий запуск (только результат)
python -m pytest tests/ -q
`

### Покрытие кода (coverage)

`powershell
# Покрытие engine-модулей (детальный отчёт в терминале)
python -m pytest --cov=docxforge.engine --cov-report=term-missing tests/

# Покрытие всех модулей (включая GUI)
python -m pytest --cov=docxforge --cov-report=term-missing tests/

# HTML-отчёт (открой htmlcov/index.html в браузере)
python -m pytest --cov=docxforge.engine --cov-report=html:htmlcov tests/
`

#### Текущее покрытие

| Модуль | Покрытие | Примечание |
|--------|----------|------------|
| `engine/schema.py` | **100%** | Полное — сериализация, десериализация, все типы полей, BatchMode |
| `engine/template_parser.py` | **97%** | Сканер плейсхолдеров, все типы (simple, today, doc_number, image) |
| `engine/data_reader.py` | **92%** | Чтение Excel, пропуск пустых строк, колонки, уникальные значения |
| `engine/renderer.py` | **90%** | Рендеринг, подстановка, циклы, агрегации, пакетная генерация, BatchMode |
| **engine (итого)** | **93%** | |
| `gui/*` | 5–7% | GUI-код требует ручного тестирования или QTest |

> Непокрытые строки renderer — это в основном edge-cases: несколько `<t>` в одном run,
> обратный поиск строки шаблона в цикле, обработка ошибок значений, поиск шаблона в подкаталогах.

### Pre-commit hook

При каждом `git commit` автоматически:
1. Запускаются тесты (`python -m pytest tests/ -q`)
2. Сканируются секреты (`trufflehog3`)

Если тесты падают — коммит отклоняется.

`powershell
# Установить хук после клонирования
scripts\install-hooks.bat
`


## Структура проекта

`
FirstAgent/
├── src/docxforge/
│   ├── engine/
│   │   ├── schema.py           # Проект, конфиг, модель данных

│   │   ├── renderer.py         # Движок рендеринга (склейка ран, подстановка, циклы)
│   │   └── data_reader.py      # Чтение Excel
│   └── gui/
│       ├── main_window.py      # Главное окно (создать/открыть проект)
│       ├── project_window.py   # Окно проекта (дерево шаблонов и данных)
│       └── fill_form.py        # Форма заполнения полей
├── docs/ideas/                 # Спецификация, DSL, тесты с пользователями
├── run.py                      # Точка входа
├── pyproject.toml              # Зависимости (uv)
