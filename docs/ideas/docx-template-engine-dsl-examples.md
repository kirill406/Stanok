# DocxForge — DSL v4: справочник и примеры

## Полный справочник DSL

### 1. Простая подстановка

```
{{ название }}
```

Значение берётся из данных. Не таблица — просто поле. Движок ищет в YAML → если нет, спрашивает в GUI.

### 2. Таблица: выбор строки

```
{{ @клиенты }}
```

@ = взять строку из таблицы. GUI покажет таблицу клиенты и предложит выбрать строку. Выбранная строка запоминается — все обращения к клиенты ниже используют ту же строку.

### 3. Таблица: столбец из выбранной строки

```
{{ @клиенты.название }}
{{ @клиенты.ИНН }}
```

Точка = разделитель «таблица.столбец». @ = таблица, после точки = столбец.

### 4. Таблица: конкретная строка по номеру

```
{{ @клиенты[3].название }}
```

Квадратные скобки — индекс строки. Третья строка, столбец «название».

### 5. Таблица: поиск строки по значению

```
{{ @клиенты[ИНН=7712345678].название }}
```

Найти строку, где столбец ИНН = 7712345678, взять название. Аналог VLOOKUP.

### 6. Спецполя

```
{{ today }}
{{ today:dd.MM.yyyy }}
{{ doc_number }}
{{ doc_number:0001 }}
```

Зарезервированные имена: 	oday, doc_number, 
ow, page. Распознаются по фиксированному списку — без угадываний.

Формат даты: dd, MM, yyyy, HH, mm, ss — стандартные Java-style паттерны.

### 7. Вычисления

```
{{ @клиенты.сумма * 1.2 }}
{{ @спецификация.итого + @спецификация.скидка }}
{{ round(@спецификация.итого, 2) }}
{{ len(@спецификация) }}
```

Операции: +, -, *, /. Функции: ound(), len().

### 8. Агрегации

```
{{ sum(@спецификация.цена) }}
{{ count(@спецификация) }}
{{ max(@спецификация.цена) }}
{{ min(@спецификация.цена) }}
```

Функции sum, count, max, min — с аргументом @таблица.столбец.

### 9. Циклы

```
{# строка in @спецификация }
{{ строка.наименование }}   {{ строка.количество }}   {{ строка.цена }}
{#/}
```

Внутри цикла строка — переменная текущей строки. Без @ = переменная цикла. С @ = таблица целиком.

### 10. Изображения

```
{{ image:логотип }}
{{ image:подпись:подпись.png }}
```

image: — явный префикс. Значение: имя из конфига или имя файла.

### 11. Алиасы (две строки из одной таблицы)

Шаблон:

```
{{ @заказчик.название }}
{{ @исполнитель.название }}
```

YAML:

```
tables:
  заказчик: клиенты
  исполнитель: клиенты
```

GUI покажет два списка выбора — оба мапятся на таблицу клиенты, но выбирают разные строки.

### 12. Пакетная генерация — через GUI

Пользователь нажимает «Сгенерировать» → модальный диалог:

- Переключатель: «Один документ» / «Несколько — по строкам таблицы»
- При выборе «Несколько»: выпадающий список таблиц-драйверов (из найденных @таблиц в шаблоне)
- @таблица-драйвер → «из очередной строки» (не список)
- @другие_таблицы → остаются выпадающими списками (фиксированный выбор)
- {{ номер }} → поле ввода + чекбокс «автоинкремент»
- Простые поля → фиксированные значения на все документы
- {{ today }}, агрегации, циклы → скрыты (движок обрабатывает автоматически)

GUI строит форму автоматически из шаблона. Никакого ручного описания полей в YAML.

## YAML-конфиг — справочник

### Минимум (80% случаев)

```
template: договор.docx
data: .
```

Движок сам найдёт Excel-файлы в папке, сам мапит имена таблиц из шаблона на имена листов.

### Средний случай

```
template: договор.docx
data: данные/клиенты.xlsx
images: [logo.png, печать.png]
```

### Полный (крайние случаи)

```
template: договор.docx
tables:
  заказчик: клиенты
  исполнитель: контрагенты
data:
  клиенты: данные/клиенты.xlsx
  спецификация: данные/спецификация.xlsx
images:
  логотип: assets/logo.png
defaults:
  номер: 1
output: output/
```

### Поля конфига

| Поле | Обязательное | Описание |
|---|---|---|
| 	emplate | да | Путь к .docx-шаблону |
| data | нет | Путь к Excel-файлу или папке с данными. По умолчанию: текущая папка |
| 	ables | нет | Маппинг алиасов: имя_в_шаблоне: имя_листа_в_excel |
| images | нет | Пути к изображениям (файлы или папки). По умолчанию: папка ssets/ |
| defaults | нет | Предзаполнение полей в GUI |
| output | нет | Папка для результатов. По умолчанию: output/ |

## Примеры шаблонов

### Пример 1: Договор поставки (один документ)

Шаблон договор_поставки.docx:

```
ДОГОВОР ПОСТАВКИ № {{ номер }}

г. Москва, «{{ today:dd }}» числа «{{ today:MM }}» месяц «{{ today:yyyy }}» г.

{{ организация }}, именуемое в дальнейшем «Поставщик», в лице {{ @поставщик.должность }} 
{{ @поставщик.фио }}, с одной стороны, и {{ @клиенты.название }}, именуемое в дальнейшем 
«Покупатель», в лице {{ @клиенты.должность }} {{ @клиенты.фио }}, с другой стороны, 
заключили настоящий Договор о нижеследующем:

1. ПРЕДМЕТ ДОГОВОРА

Поставщик обязуется поставить, а Покупатель — принять и оплатить следующие товары:

{# строка in @спецификация }
{{ строка.наименование }}    {{ строка.количество }}    {{ строка.цена }} руб.
{#/}

Итого: {{ sum(@спецификация.цена) }} руб.
С НДС (20%): {{ sum(@спецификация.цена) * 1.2 }} руб.

{{ image:логотип }}
{{ image:подпись:подпись_директора.png }}
```

YAML договор_поставки.yaml:

```
template: договор_поставки.docx
data: данные/
tables:
  поставщик: сотрудники
images:
  логотип: assets/logo.png
  подпись: assets/signatures/
defaults:
  номер: 1
  организация: ООО «Рога и копыта»
output: output/
```

GUI-диалог при генерации:

- **Один документ** / ☑ Несколько — по строкам [клиенты ▼]
- номер: [1] авто ☑
- организация: [ООО «Рога и копыта»] (предзаполнено из defaults)
- @клиенты: [ООО «Альфа» ▼] (выбор строки)
- @поставщик: [Иванов И.И. ▼] (выбор строки из таблицы «сотрудники»)
- логотип: [logo.png 📎]
- подпись: [подпись_директора.png 📎]

### Пример 2: Приказы по сотрудникам (пакетная генерация)

Шаблон приказ_увольнение.docx:

```
ПРИКАЗ № {{ номер }}

от {{ today:dd.MM.yyyy }}

Об увольнении {{ @сотрудники.фио }}, табельный номер {{ @сотрудники.табельный_номер }},
из отдела {{ @сотрудники.отдел }}, с должности {{ @сотрудники.должность }},
с «{{ @сотрудники.дата_увольнения }}» г.

Основание: {{ @сотрудники.основание }}

Руководитель: {{ руководитель }}
{{ image:подпись }}
```

YAML приказ_увольнение.yaml:

```
template: приказ_увольнение.docx
data: данные/сотрудники.xlsx
images:
  подпись: assets/signature_director.png
defaults:
  руководитель: Иванов А.Б.
output: output/приказы/
```

GUI-диалог:

- ☑ Несколько — по строкам [сотрудники ▼] → 47 документов
- номер: [1] авто ☑ (начнёт с 1)
- руководитель: [Иванов А.Б.] (предзаполнено)
- today: скрыто (автоматически)
- @сотрудники: «из очередной строки» ✓
- подпись: [signature_director.png 📎]

Результат: 47 файлов с именами 2026_приказ_0001_Сидоров_К.Л.docx, 2026_приказ_0002_Петров_М.Н.docx и т.д.

### Пример 3: Договор с поручителем (алиасы)

Шаблон договор_с_поручителем.docx:

```
Договор займа № {{ номер }}

Займодавец: {{ @займодавец.название }}, ИНН {{ @займодавец.ИНН }}
Заёмщик: {{ @заёмщик.название }}, ИНН {{ @заёмщик.ИНН }}
Поручитель: {{ @поручитель.название }}, ИНН {{ @поручитель.ИНН }}
```

YAML:

```
template: договор_с_поручителем.docx
data: данные/контрагенты.xlsx
tables:
  займодавец: контрагенты
  заёмщик: контрагенты
  поручитель: контрагенты
output: output/
```

GUI: три выпадающих списка — все из таблицы «контрагенты», но три разные строки.

---

### Пример 4: Поиск по значению (VLOOKUP)

Шаблон:

```
Справка

Контрагент: {{ @клиенты[ИНН=7712345678].название }}
Адрес: {{ @клиенты[ИНН=7712345678].адрес }}
```

Движок сам найдёт строку с ИНН=7712345678 и подставит название и адрес. GUI не показывает список — значение задано прямо в шаблоне.

### Пример 5: Конкретная строка по номеру

Шаблон:

```
Ставка рефинансирования: {{ @ставки[1].значение }}%
```

Первая строка таблицы «ставки», столбец «значение».

## Стресс-тест и допущения (Phase 2 — краткая выжимка)

Полная версия — в основном документе docx-template-engine.md.

### Ключевые риски

| # | Риск | Вероятность | Предотвращение |
|---|---|---|---|
| 1 | Склейка ран ломает форматирование | Высокая | Протестировать на 10 реальных шаблонах ДО написания движка |
| 2 | DSL слишком сложен для пользователей | Средняя | Тест с 2 сотрудниками + инструкция на 1 страницу |
| 3 | Движок ломает сложные docx | Средняя | Начать с простых шаблонов, документировать ограничения |
| 4 | Excel-данные — мусор | Средняя | Валидация данных + понятные сообщения об ошибках |
| 5 | Сложная установка | Средняя | PyInstaller .exe с первого спринта |
| 6 | Медленная генерация | Низкая | Прогресс-бар + отмена + замеры |

### Допущения-убийцы (Must Be True)

1. Склейка XML-ран работает на ≥70% реальных шаблонов
2. Нетехнический сотрудник может написать {{ @таблица.столбец }} по инструкции
3. Движок корректно обрабатывает .docx XML без слёта форматирования
