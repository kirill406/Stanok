# DocxForge — Python Docx-шаблонизатор

## Problem Statement

Как сделать так, чтобы сотрудник отдела, имея десятки типов документов и разрознённые таблицы с данными, получал готовый .docx в несколько кликов — без ручного ввода, без расхождения стилей и без программирования?

## Роли

| Роль | Что делает | Уровень подготовки |
|---|---|---|
| **Пользователь** | Запускает GUI, выбирает шаблон, настраивает поля в форме, генерирует документы | Обычный сотрудник отдела — уверенный Word + Excel |
| **Администратор** | Размечает .docx-шаблоны (вставляет {{ поле }}), создаёт и настраивает проект | Тот же сотрудник — может выступать в роли администратора. Разметка шаблона не должна требовать специальных знаний |
| **Разработчик** | Имеет доступ к коду, добавляет фичи, исправляет баги | Программист |

Администратор = обычный пользователь. Поэтому шаблон должен быть **предельно простым**: только {{ имя }}. Вся сложность — в GUI.

## Рекомендуемое направление

Десктопное приложение (PyQt/PySide + python-docx).

**Шаблон (.docx)** содержит только {{ имя_поля }} — и ничего больше. Никаких @, никаких {# цикл #}, никаких sum(). Поля выглядят как обычный текст с фигурными скобками.

**Вся настройка — в GUI.** Пользователь (или администратор) вручную маппит каждое поле на источник данных: константа, таблица Excel, счётчик, текущая дата, изображение. Циклы и агрегации вынесены в раздел «Дополнительно» — GUI маппит участок документа на таблицу.

**.docxforge-файл** хранит маппинг. Пользователь никогда его не видит — GUI читает и пишет автоматически. Никаких YAML-конфигов.

### Проект = папка

`
МойПроект/
├── Данные/                     ← администратор копирует сюда .xlsx
│   ├── клиенты.xlsx
│   ├── сотрудники.xlsx
│   └── спецификация.xlsx
├── Шаблоны/                    ← администратор создаёт/копирует .docx
│   ├── Договоры/               ← можно вложенные папки
│   │   ├── договор_поставки.docx
│   │   └── договор_услуги.docx
│   └── Приказы/
│       ├── приказ_увольнение.docx
│       └── приказ_приём.docx
└── проект.docxforge            ← автоматический файл маппинга (JSON)
`

## DSL v5: что администратор пишет в шаблоне

**Только** {{ имя_поля }}. Плюс три спецпрефикса, распознаваемых автоматически.

### Основное: произвольное поле

`
{{ название_клиента }}
{{ ИНН }}
{{ сумма_договора }}
{{ ответственный }}
`

**Любой текст** внутри {{ }}. Движок НЕ знает, откуда данные. GUI покажет это поле в форме — и пользователь выберет источник.

### Спецполя (распознаются автоматически)

`
{{ today }}
{{ today:dd.MM.yyyy }}
{{ doc_number }}
{{ doc_number:0001 }}
`

	oday и doc_number — зарезервированные имена. GUI не показывает их в форме — подставляются автоматически.

### Изображения

`
{{ image:логотип }}
{{ image:подпись }}
`

image: — единственный префикс в шаблоне. В GUI: выбор файла.

### Итого: что видит администратор

| Можно писать в шаблоне | Пример |
|---|---|
| {{ что_угодно }} | {{ название }}, {{ дата_рождения }}, {{ сумма * 1.2 }} |
| {{ today }}, {{ today:формат }} | {{ today:dd.MM.yyyy }} |
| {{ doc_number }}, {{ doc_number:формат }} | {{ doc_number:0001 }} |
| {{ image:имя }} | {{ image:логотип }} |

**Нельзя** писать в шаблоне (это работа пользователя в GUI):
- {@таблица.столбец} — убрано после теста
- {# цикл #} — настраивается в Дополнительно
- {{ sum() }} — настраивается в Дополнительно

### Типы источников (выпадающий список «Тип»)

| Тип | Что заполняет пользователь | Пример |
|---|---|---|
| **Константа** | Значение — вручную | "ООО Ромашка" |
| **Таблица** | Excel-файл → столбец → строка | клиенты.xlsx → название → строка 3 |
| **Счётчик** | Начальное значение, шаг, формат | старт=1, шаг=1, формат  001 |
| **Сегодня** | Формат даты | dd.MM.yyyy |
| **Изображение** | Файл картинки | logo.png |

### Связка полей из одной таблицы — автоматическая

Если {{ название_клиента }} и {{ ИНН_клиента }} оба мапятся на клиенты.xlsx, GUI:
1. При выборе строки в первом поле — автоматически подставляет значения во все связанные поля
2. Показывает «та же, что для „название_клиента“» в связанных полях

Пользователь не настраивает связку вручную — она выводится из маппинга.

### Связка полей для разных таблиц — не нужна

Если {{ название_клиента }} → клиенты.xlsx, а {{ ИНН_поручителя }} → контрагенты.xlsx — это два независимых выпадающих списка. Пользователь выбирает строки отдельно.

## Раздел «Дополнительно» (разворачивается по клику)

Пользователь раскрывает, если в шаблоне есть повторяющиеся блоки или итоговые суммы.

`
│▾ Дополнительно                                    │
│                                                   │
│  ┌─────────────────────────────────────────────┐ │
│  │ Цикл 1                                      │ │
│  │                                             │ │
│  │ Таблица: [спецификация.xlsx ▼]              │ │
│  │                                             │ │
│  │ Поля в цикле:                               │ │
│  │ ┌───────────────────────────────────────┐  │ │
│  │ │ наименование → столбец [наименование ▼]│  │ │
│  │ │ количество    → столбец [количество ▼] │  │ │
│  │ │ цена          → столбец [цена ▼]       │  │ │
│  │ └───────────────────────────────────────┘  │ │
│  │                                  [Удалить] │ │
│  └─────────────────────────────────────────────┘ │
│                                                   │
│  ┌─────────────────────────────────────────────┐ │
│  │ Агрегация 1                                 │ │
│  │                                             │ │
│  │ Поле в шаблоне: {{ итого }}                 │ │
│  │ Формула: [sum          ▼]                   │ │
│  │ Таблица: [спецификация.xlsx ▼]              │ │
│  │ Столбец: [цена ▼]                           │ │
│  │                                  [Удалить] │ │
│  └─────────────────────────────────────────────┘ │
│                                                   │
│  ┌─────────────────────────────────────────────┐ │
│  │ Агрегация 2                                 │ │
│  │                                             │ │
│  │ Поле в шаблоне: {{ с_ндс }}                 │ │
│  │ Формула: [сумма * число ▼]                  │ │
│  │ Таблица: [спецификация.xlsx ▼]              │ │
│  │ Столбец: [цена ▼]                           │ │
│  │ Множитель: [1.2             ]               │ │
│  └─────────────────────────────────────────────┘ │
│                                                   │
│                              [ + Добавить цикл ]  │
│                              [ + Добавить агрегацию ]│
`

Агрегации добавляются пользователем **вручную** через кнопки. Доступные агрегации:

| Функция | Описание |
|---|---|
| sum | Сумма по столбцу |
| sum * N | Сумма по столбцу, умноженная на N |
| count | Количество строк |
| max | Максимум |
| min | Минимум |

## Флоу: Администратор готовит проект

`
1. Создаёт папку проекта, копирует туда .xlsx в Данные/
2. В Word размечает шаблон: вставляет {{ название_клиента }}, {{ ИНН_клиента }}, {{ today }}, {{ doc_number }} и т.д.
3. Копирует .docx в Шаблоны/ (можно в подпапки)
4. Запускает DocxForge → Открыть проект → выбирает папку
5. Для каждого шаблона жмёт [Заполнить] → настраивает поля в GUI
6. В «Дополнительно» настраивает циклы и агрегации (если нужно)
7. Настройки сохраняются в проект.docxforge
`

## Флоу: Пользователь генерирует документ

`
1. Запускает DocxForge → Открыть проект
2. Видит дерево шаблонов
3. Жмёт [Заполнить] рядом с нужным шаблоном
4. Все поля уже настроены администратором
5. Выбирает нужные значения в выпадающих списках (клиента, сотрудника и т.д.)
6. Выбирает «один» или «несколько» документов
7. Жмёт [Создать]
8. Получает готовый .docx
`

## Сравнение: до и после теста

| Что | DSL v4 (до теста) | DSL v5 (после теста) |
|---|---|---|
| Поле в шаблоне | {{ @клиенты.название }} | {{ название_клиента }} |
| Связь с таблицей | Через @ и . в шаблоне | Выпадающие списки в GUI |
| Циклы | {# строка in @спецификация } в docx | Раздел «Дополнительно» в GUI |
| Агрегации | {{ sum(@спецификация.цена) }} в docx | Раздел «Дополнительно» в GUI |
| Конфиг | YAML-файл (редактируемый вручную) | .docxforge JSON (только через GUI) |
| Проект | Шаблон + YAML рядом | Папка с Шаблоны/ + Данные/ |
| Главное окно | Сразу генерация | Кнопки «Создать новый проект» + «Открыть проект» |
| Шаблон содержит | 10 конструкций DSL | Только {{ имя }} + {{ image:имя }} |

## Key Assumptions to Validate

- [ ] **Склейка XML-ран работает.** Протестировать на 10 реальных шаблонах. Если >20% ломаются → SDT.
- [ ] **Пользователь НЕ путается в форме GUI.** Провести тест новой версии с теми же 3–5 сотрудниками. Дать готовый проект (поля уже настроены) — проверить, может ли пользователь заполнить форму и сгенерировать документ.
- [ ] **Автосвязка полей работает.** GUI правильно определяет, что поля из одной таблицы связаны, и подставляет значения.
- [ ] **Раздел «Дополнительно» понятен** для администратора, настраивающего циклы и агрегации.
- [ ] **PyInstaller собирает рабочий .exe.** Протестировать на чистой Windows.
- [ ] **Excel-данные достаточно структурированы.** Проверить 3–5 реальных Excel-файлов.

## MVP Scope (обновлённый порядок)

1. **Прототип склейки XML-ран** — проверить на 10 реальных шаблонах
2. **Парсер шаблона** — найти все {{ }}, {{ image: }}, {{ today }}, {{ doc_number }}
3. **Главное окно** — «Создать новый проект» / «Открыть проект» / недавние проекты
4. **Окно проекта** — дерево Шаблонов, список Данных
5. **Форма заполнения** — список полей, типы источников, выпадающие списки, автосвязка
6. **Раздел «Дополнительно»** — циклы, агрегации
7. **Пакетная генерация** — переключатель «один/несколько», прогресс-бар, отмена
8. **Движок подстановки** — поля, таблицы, изображения, циклы, агрегации
9. **.docxforge-файл** — чтение/запись JSON, невидимый для пользователя
10. **PyInstaller .exe** — собирается и тестируется с первого спринта

## Not Doing (и почему)

- **Веб-интерфейс** — по требованиям: не веб-приложение
- **Маршруты согласования** — out of scope
- **Коллаборативное редактирование** — out of scope
- **Jinja2 / @ / {# #} / sum() в шаблоне** — тест показал: слишком сложно. Убрано.
- **YAML-конфиг, редактируемый вручную** — GUI управляет маппингом через .docxforge JSON
- **Визуальный конструктор полей** — дорого; форма с выпадающими списками — достаточно
- **AI-assisted генерация** — рано
- **Условия (if/else)** — MVP не требует
- **Вложенные циклы** — MVP не требует
- **Декартово произведение в batch** — риск взрыва документов
- **Группировка по столбцу** — v2
- **Диапазоны дат и чисел** — v2
- **Таблица рецептов** — v2
- **Ручной парсер DSL** — {{ }} распарсить тривиально, pyparsing/lark не нужен для v5
