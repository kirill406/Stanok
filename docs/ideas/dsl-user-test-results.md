# Результаты теста DSL с пользователями

## Дата: 04.09.2026

## Результат: ПРОВАЛ

Пользователи не смогли освоить DSL v4. Ключевые проблемы:

### Что не сработало

1. **Символ @ для обращения к таблицам** — путаница. Пользователи не понимали, зачем он нужен и когда его ставить.
2. **Точка как разделитель таблица.столбец** — вызывала вопросы. Пользователи путали порядок (столбец.таблица вместо таблица.столбец).
3. **Циклы {# строка in @таблица } … {#/}** — слишком похоже на программирование. Отторжение.
4. **Агрегации {{ sum(@таблица.столбец) }}** — пользователи не понимали, что писать внутри скобок.
5. **Общее ощущение: «это код, а не документ»** — шаблон переставал выглядеть как документ.

### Что сработало

- {{ today }} и {{ doc_number }} — понятно сразу
- {{ image:имя }} — понятно
- {{ простое_поле }} — понятно
- Идея «размечаешь документ — получаешь результат» — понравилась

## Принятые решения

| Проблема | Решение |
|---|---|
| @ сбивает с толку | **Убрать @.** Шаблон содержит только {{ имя }} |
| Точка путает | **Убрать точку.** Связь поля с таблицей настраивается в GUI |
| Циклы — слишком сложно | **Перенести в «Дополнительно».** GUI маппит участок документа на таблицу |
| Агрегации — слишком сложно | **Перенести в «Дополнительно».** GUI задаёт формулу выпадающими списками |
| Шаблон выглядит как код | **Только {{ имя }}.** Шаблон выглядит как документ с пометками |

## Новая модель (DSL v5)

- Администратор: размечает шаблон только {{ имя }}. Вся настройка — в GUI.
- Пользователь: только заполняет готовую форму. Не видит ни маппинг, ни .docxforge.
- Проект: папка с Шаблоны/ + Данные/. GUI строит дерево шаблонов автоматически.
- Главное окно: «Создать новый проект» / «Открыть проект» / недавние проекты.
