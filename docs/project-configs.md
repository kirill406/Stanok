# Конфиги проектов: именованные файлы, миграция, резолвер

Graduated from `specs/002-stabilization/` (Status: done).

## Правило
Фиксированного `проект.docxforge` нет. Каждый проект владеет
`<название>.docxforge` (`проект1` → `проект1.docxforge`).

## Жизненный цикл
- Создание (вручную, flat, nested, engine) пишет именованный конфиг рядом
  с `Данные/` и `Шаблоны/`.
- При старте (по недавним папкам) и при открытии папки конфиги мигрируют:
  данные переносятся в `~/.docxforge/<имя_папки>.docxforge`
  (коллизия → `(1)`, `(2)`), исходник из папки удаляется.
- Открытие гибридное: конфиг из папки или Home-копии, `Данные/`/`Шаблоны/`
  всегда из папки; сохранения пишутся обратно в открытый файл.

## Резолвер (`engine/schema.py`)
`resolve_project_file()`: именованный в папке → legacy `проект.docxforge` →
единственный `*.docxforge` → Home-копия (точная → `(n)` newest).
`is_project_folder()`, `migrate_project_configs_to_home()`,
`default_project_file()` — там же. GUI/CLI читают и сохраняют только
через резолвер.

## Тесты

  round-trip через Renderer.
