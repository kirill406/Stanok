# Архитектура Stanok (рерайт)

Производная от `mistakes.md`: каждое решение закрывает конкретную ошибку
FirstAgent (ссылки `M1–M12`). Детальные границы слоёв — в `layers.md`.

## Принципы
- **Один use case — одна функция** (M2). Flat/nested — параметры
  (`folder_template`), не копии кода.
- **Конвейер со стадиями и DTO** (M3): `строки → Filling JSON → docx`.
  Стадия не знает соседей; между стадиями — типизированные структуры,
  не сырые dict'ы из Excel.
- **Версионированные форматы файлов** (M1, M8): каждый JSON имеет `version`;
  реестр миграций `migrations/`; ломающее = bump + CHANGELOG + тест миграции.
- **Хранилища инжектируются** (M4, M11, M12): движок принимает `ProjectStore`,
  `TableReader`, `LogSink` параметрами; никаких `~/.stanok` и диалогов внутри.
- **Контракты до параллельной работы** (M6): сигнатура + тест контракта
  на каждую границу; `getattr`-флаги запрещены.
- **Сборка как код** (M9): `scripts/build-exe.*` в репозитории, CI проверяет.

## Модули (`src/stanok/`)
```
src/stanok/
├── app.py            # bootstrap: parse args → wire storage → run (M12: без side effects на import)
├── engine/           # чистый Python, ноль Qt/GUI (M4)
│   ├── schema.py     # PJ/AJ/Filling типы + validate/normalize + реестр миграций (M1, M6)
│   ├── tables.py    # Excel → строки, ОДИН раз на границе (M5)
│   ├── resolve.py   # строки → Filling JSON: одна семантика (M3, M7)
│   ├── render.py    # Filling JSON → docx: ТОЛЬКО подстановка (M3)
│   └── xmlops.py    # run-merge, циклы, картинки (низкоуровневый XML)
├── services/         # use cases, по одному на сценарий (M2)
│   ├── generate.py  # сгенерировать документы (flat/nested параметром)
│   ├── projects.py  # создать/открыть/удалить проект, именованные конфиги (M1)
│   ├── migrate.py   # миграции форматов + перенос в ~/.stanok (M1, M11)
│   └── storage.py   # ProjectStore: файлы, уникальные имена, атомарная запись (M4)
├── gui/              # тонкий Qt: окна → вызовы services, ноль бизнес-логики (M4)
├── cli/              # тонкий CLI поверх тех же services
└── tables/           # бэкенды чтения (excel.py сейчас; csv/ — позже) (M5)
```

## Данные (JSON, см. спеки 003-json как стартовую точку)
- **PJ** (`<имя>.stanok.json`? имя обсудить — см. вопрос ниже): конфиг проекта,
  `version`, словарь шаблонов, относительные пути.
- **FJ**: разрешённые данные документа (`{template, fields, images?}`) —
  единственный вход рендера.
- **AJ** (`~/.stanok/settings.json`): недавние + настройки, без шаблонов/счётчиков.
- Фикстуры тестов — `tests/json/<кейс>/` (M5, M7): xlsx + docx + filling.json + эталон.

## Открытые решения (требуют ответа до кодирования движка)
1. **Имя файла конфига**: оставить `<имя>.docxforge` (совместимость чтения
   с FirstAgent) или `<имя>.stanok.json` (чистый разрыв)? Рерайт позволяет
   разрыв, но чтение старых проектов — ценная фича. Решить и зафиксировать
   в спеке до кодирования движка.
2. **Связь GUI↔services**: прямые вызовы (как сейчас) или команды с очередью
   (нужно для отмены фоновых задач M10)? 
3. **Тест границ слоёв**: падение CI при импорте Qt в engine и при импорте
   gui→gui в обход services — добавить `tests/test_layers.py` с первого дня (M7).
4. **Версия формата vs версия продукта**: независимые счётчики (`format: 2`,
   `app: 0.x`) или единый? Предлагаю независимые.
