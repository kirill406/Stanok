# Архитектура Stanok (рерайт)

Производная от `mistakes.md`: каждое решение закрывает конкретную ошибку
FirstAgent (ссылки `M1–M12`). Детальные границы слоёв — в `layers.md`.

## Принципы
- **Один use case — одна функция** (M2). Flat/nested — параметры
  (`folder_template`), не копии кода.
- **Конвейер со стадиями и DTO** (M3): `строки → Filling JSON → docx`.
  Стадия не знает соседей; между стадиями — типизированные структуры,
  не сырые dict'ы из Excel.
- **Версионированные форматы файлов** (M1, M8): каждый JSON имеет `version`;
  реестр миграций `migrations/`; ломающее = bump + CHANGELOG + тест миграции.
- **Хранилища инжектируются** (M4, M11, M12): движок принимает `ProjectStore`,
  `TableReader`, `LogSink` параметрами; никаких `~/.stanok` и диалогов внутри.
- **Контракты до параллельной работы** (M6): сигнатура + тест контракта
  на каждую границу; `getattr`-флаги запрещены.
- **Сборка как код** (M9): `scripts/build-exe.*` в репозитории, CI проверяет.

## Модули (`src/stanok/`)
```
src/stanok/
├── app.py            # bootstrap: parse args → wire storage → run (M12: без side effects на import)
├── engine/           # чистый Python, ноль Qt/GUI (M4)
│   ├── schema.py     # PJ/AJ/Filling типы + validate/normalize + реестр миграций (M1, M6)
│   ├── tables.py    # Excel → строки, ОДИН раз на границе (M5)
│   ├── resolve.py   # строки → Filling JSON: одна семантика (M3, M7)
│   ├── render.py    # Filling JSON → docx: ТОЛЬКО подстановка (M3)
│   └── xmlops.py    # run-merge, циклы, картинки (низкоуровневый XML)
├── services/         # use cases, по одному на сценарий (M2)
│   ├── generate.py  # сгенерировать документы (flat/nested параметром)
│   ├── projects.py  # создать/открыть/удалить проект, именованные конфиги (M1)
│   ├── migrate.py   # миграции форматов + перенос в ~/.stanok (M1, M11)
│   └── storage.py   # ProjectStore: файлы, уникальные имена, атомарная запись (M4)
├── gui/              # тонкий Qt: окна → вызовы services, ноль бизнес-логики (M4)
├── cli/              # тонкий CLI поверх тех же services
└── tables/           # бэкенды чтения (excel.py сейчас; csv/ — позже) (M5)
```

## Данные (JSON, см. спеки 003-json как стартовую точку)
- **PJ** (`<имя>.stanok.json`? имя обсудить — см. вопрос ниже): конфиг проекта,
  `version`, словарь шаблонов, относительные пути.
- **FJ**: разрешённые данные документа (`{template, fields, images?}`) —
  единственный вход рендера.
- **AJ** (`~/.stanok/settings.json`): недавние + настройки, без шаблонов/счётчиков.
- Фикстуры тестов — `tests/json/<кейс>/` (M5, M7): xlsx + docx + filling.json + эталон.

## Решения (приняты до кодирования движка)
1. **Имя файла конфига — РЕШЕНО**: `<имя>.stanok`, внутри JSON. Прошлая
   версия забывается полностью: не читаем, не мигрируем.
   Детали и все вытекающие проблемы — в разделе «Файл `<имя>.stanok`» ниже.
2. **Связь GUI↔services — РЕШЕНО**: прямые вызовы. Очередь команд не вводим
   (отмена фоновых задач — через существующий worker с флагом, как в M10).
3. **Тест границ слоёв**: падение CI при импорте Qt в engine и при импорте
   gui→gui в обход services — добавить `tests/test_layers.py` с первого дня (M7).
4. **Версия формата vs версия продукта — РЕШЕНО**: единый счётчик.
   Версия приложения = версия формата (один `version` в `pyproject.toml`,
   дублируется в `__init__.py` и в поле `version` каждого файла).

## Файл `<имя>.stanok` (решение + анализ проблем)

**Решение.** Конфиг проекта — файл `<имя>.stanok`, внутри чистый JSON по схеме
PJ. Двойное расширение (`.stanok.json`) отклонено: уродует имена и ломает
правило «имя файла = имя проекта». Прошлая версия не читается
и не мигрируется — осознанный разрыв.

### Проблема 1. Старые проекты не открываются
Папка проекта прошлой версии (без `*.stanok`) должна давать
понятную ошибку, а не молчание или падение: «Проект создан в предыдущей
версии — создайте заново». Детект — по наличию конфигов прошлого формата
при отсутствии `*.stanok`. Тест: фикстура такой папки → диалог, не исключение.

### Проблема 2. Ассоциация файлов в Windows
Двойной клик заработает только после регистрации расширения (реестр/инсталлер);
портативный exe регистрировать не может. До инсталлера — инструкция
«Открыть с помощью» в README/FAQ + иконка, зашитая в exe. Задача на инсталлер —
отдельная спека, не MVP.

### Проблема 3. Поддержка редакторов
`.stanok` неизвестен редакторам: подсветки/валидации из коробки нет.
Лечится документированием (`files.associations: {"*.stanok": "json"}` в README
для разработчиков) и командой `stanok validate <файл>` (будущий CLI).
Контент остаётся валидным JSON — `jq` и скрипты работают без доработок.

### Проблема 4. Правила имён (Windows)
- Санитизация: `<>:"/\|?*`, control-chars, точки/пробелы в конце (наследуем
  правила FirstAgent + тесты).
- Регистр: `Договор.stanok` и `договор.stanok` — один файл на Windows;
  сравнение имён всегда case-insensitive.
- Зарезервированные имена (`CON`, `PRN`, `NUL`, …): запретить явно с понятной
  ошибкой, иначе Windows молча сломает файл.
- Длина: запас под `MAX_PATH` (stem ≤ 100 символов, как было).
- Коллизии: `(1)`, `(2)` для создаваемого; существующий не трогаем.

### Проблема 5. Версия формата внутри файла
Поле `"version"` равно версии приложения (единый счётчик, решение 4):
`pyproject.toml` → `__init__.py` → каждый файл. Неизвестная новая версия →
явная ошибка «обновите программу», а не парсинг мусора. Каждая версия
формата — тест round-trip.

### Проблема 6. Битые файлы
Guards с первого дня (урок B3): битый JSON → диалог, не падение; запись —
атомарная через tmp+rename с `.bak` (урок M4/M12). Тесты на каждый guard.

### Проблема 7. Связь с миграцией в Home
Механика FirstAgent сохраняется: конфиг живёт в папке, при открытии
мигрирует в `~/.stanok/<имя_папки>.stanok`, исходник удаляется; резолвер
папка → именованный → Home. Переименование папки после миграции разрывает
связь — задокументированное ограничение (как было).

### Проблема 8. Тесты и репозиторий
Фикстуры — текстовые `.stanok` (диффы читаются — преимущество перед xlsx).
Контрактные тесты схемы + тест границ слоёв (`tests/test_layers.py`).
`Результат/` — в `.gitignore` пользовательских проектов (рекомендация в доке).

### Проблема 9. Безопасность чтения с диска
Строгая валидация схемы (неизвестные ключи — варнинг, не падение);
path traversal через `filename_template` (`../`) — санитизация выходных
путей с тестом; лимит размера JSON (защита от гигантов, число зафиксировать
в спеке: предлагаю 10 МБ).

### Проблема 10. AJ ссылается на проекты по имени
Переименование `<имя>.stanok` в Home вручную ломает связь с recent-записью.
Решение: recent хранит пару (папка + имя конфига); при рассинхроне —
резолвер по папке (как сейчас), запись AJ обновляется молча. Ручное
переименование внутри Home без папки — unsupported, документировать.
