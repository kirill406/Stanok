# SPEC.md — 002-stabilization (доводка продукта)

Status: draft. Branch: `spec-002`.

## Goal
Довести «Станок» до стабильного состояния: предсказуемое создание
генерируемых проектов, сохраняемые логи, отсутствие падений, контроль
копирования таблиц, защита от перезаписи, корректные счётчики.
Ранее готовое (мультивыбор папок, папка `Результат`, дефис перед полем) —
сверить и зафиксировать как done с доказательством.

## Блоки (непересекающиеся, для параллельной работы)

### B0 «Сверка готового»
Подтвердить и зафиксировать как done с доказательством (коммит + тест/поведение):
- Множественный выбор папок проектов (кнопка в главном окне, валидные папки —
  в недавние, остальные — в сводку).
- Папка вывода генерации — `Результат` (каталога `output` нет в коде и на диске).
- Дефис перед полем не съедается: `текст-текст{{поле}}` рендерится с дефисом.
Gaps → отдельные follow-up задачи, не молчаливое закрытие.

### B1 «Генерируемые проекты»
- Файл `проект.docxforge` именуется по названию самого проекта и сохраняется
  в домашнюю папку пользователя (Home).
- Папки `шаблоны/` внутри генерируемых проектов заполнены (не пустые).
- В окно заполнения шаблона добавляется секция «Поля шаблона для генерируемых
  проектов»: заданные в ней поля определяют отдельный шаблон файла
  `проект.docxforge` для генерируемых проектов.

### B2 «Логи»
- Общий лог приложения не теряется: пишется в файл в домашней папке
  пользователя (Home), переживает перезапуск программы.
- Путь и имя файла — константа в одном месте (без хардкода по коду).

### B3 «Падение из меню заполнения»
- Воспроизвести падение при создании из меню заполнения шаблонов, зафиксировать
  traceback в задаче.
- Исправить причину; добавить регрессионный тест, воспроизводящий сценарий.

### B4 «Исключение копирования»
- При генерации проектов у каждой таблицы чекбокс «Исключить копирование»
  (строка через `STRINGS`, без хардкода русского текста).
- Исключённые таблицы не копируются в папку `Данные/` генерируемого проекта;
  остальные копируются как раньше.

### B5 «Защита от перезаписи и недавние»
- Генерация из главного меню не перезаписывает файлы: если файл существует,
  создаваемый файл переименовывается (`файл (1)`, `файл (2)`, …).
- Запись недавних проектов расширена: `[название, путь, шаблон, счётчики]`
  с миграцией старого формата (строка-путь) без потери данных.

### B6 «Счётчик при создании из генерации»
- Создание документов/проектов из генерации прибавляет счётчик так же, как
  обычная генерация.
- Сценарий покрыт регрессионным тестом (было/стало по значению счётчика).

## Non-overlap contract
Каждый блок работает только в своей зоне; общие файлы — по минимуму,
с `git pull` и мелкими коммитами:
- B1: `generate.py` (создание проектов), project I/O, окно заполнения шаблона.
- B2: logging setup.
- B3: fill-form entry points.
- B4: GUI таблиц + флаги копирования.
- B5: главное меню + recent storage.
- B6: engine counter path.
- B0: только чтение + фиксация (код — лишь micro-fix отдельной веткой).

## Acceptance
- Каждый блок: поведение проверено + тест (для B3, B5, B6 — обязательно;
  для GUI — pytest-qt либо ручной чек-лист, приложенный к задаче).
- `pytest tests/ -q` зелёный после каждого блока.
- Конвенции репо: `logging` вместо `print`, RU-строки через `STRINGS`,
  багфикс → регрессионный тест, коммит на задачу.

## Out of scope
- Фичи вне перечисленных блоков.
- CLI-паритет (отдельная работа, см. `docs/cli-gui-parity.md`).
