# SPEC.md — 003-json (слой JSON-данных)

Status: draft. Branch: `spec-003` (создать от `main`).

## Goal
Ввести явный JSON-слой данных между Excel и рендером: движок читает таблицы
один раз (Excel → JSON), дальше всё — генерация, счётчики, тесты — работает
поверх разрешённых JSON-данных. Убрать неявные поиски по Excel из глубины
движка, сделать рендер тестируемым JSON-фикстурами.

## Три типа JSON (примеры — файлы рядом, нормативные)
- **`project_generation.json` — Project JSON.** Конфиг проекта: шаблоны →
  поля (маппинг), пакетные источники, `resume`. Значения-маппинги могут
  содержать плейсхолдеры. Схема — словарь `templates` (вариант `templates_new`
  массивом — отклонён). Пути только относительные.
- **`template_filling.json` — Filling JSON.** Разрешённые данные одного
  документа: ссылка на шаблон, путь результата, поля `{name: value}` —
  только разрешённые значения, плейсхолдеров нет.
- **`docxforge_settings.json` — Application JSON.** Список недавних проектов
  и настройки приложения. Шаблонов и счётчиков нет — они в Project JSON.

## Scope
- Только движок (`render`, `data_formatting`, `schema`); Excel остаётся входом,
  GUI/CLI — без изменений поведения.
- Strangler: новый код рядом, пути переключаются по одному, тесты зелёные
  после каждого шага. Ломающие изменения формата — только с записью
  в CHANGELOG и миграцией legacy.

## Non-overlap contract (для параллельных агентов)
- P1: `renderer.py` — вход `render_from_json()` (Filling JSON → docx).
- P2: `data_reader.py` + новый `data_formatting` — граница Excel → JSON.
- P3: `schema.py` — нормализация Project JSON (словарь, относительные пути).
- P4: `generate.py` — переключение путей создания на JSON (по одному).
- Общее: тесты рядом с кодом; `gui/`, `cli/` не трогать.

## Acceptance
- Рендер из JSON-фикстуры без Excel (новый тест).
- Граница Excel → JSON покрыта: типы, режимы строк, счётчики, resume.
- Полный `pytest tests/ -q` зелёный; поведение GUI/CLI не изменилось.
- Примеры в папке соответствуют спеке (см. «Требуют правки» ниже).

## Тестирование через JSON-слой (`tests/json/`)
- Каждый тест — подпапка `tests/json/<имя>/`: исходники (`data.xlsx`,
  `template.docx`, `filling.json`) + эталон `expected.docx`.
- `tests/test_json_fixtures.py` параметризован по подпапкам: рендерит шаблон
  данными из `filling.json`, сравнивает текст с эталоном.
- Сравнение текстовое (параграфы + ячейки по порядку); форматирование,
  картинки и метаданные не сравниваются (байтовое сравнение невозможно).
- Новый JSON-тест = новая подпапка, код теста не меняется.

## Требуют правки (примеры пока черновые)
- `project_generation.json`: удалить дубль `templates_new`, значения вида
  `"{{ организация }}"` заменить на маппинг без плейсхолдеров либо вынести
  в Filling; все пути — относительные; `type: number` замаппить на COUNTER;
  `filename_template` без абсолютных путей.
- `template_filling.json`: пути (`template_path`, `dist_path`) — относительные.
- `docxforge_settings.json`: папки (`///Петров П.П`) — относительные/валидные;
  богатые recent — только если решим reversal 002 (пока хранить минимум).

## Out of scope
- Переписывание GUI/CLI; облачные источники; смена формата `.docxforge`
  сверх нормализации; PDF и другие выходы.
