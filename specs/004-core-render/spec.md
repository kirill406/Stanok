**NFR:** NFR-4

---

## 1. Назначение

Единственный модуль, превращающий разрешённые данные в документ:
берёт `FillingJSON` + файл шаблона `.docx` → возвращает готовый `.docx`
в памяти. Подстановка сохраняет форматирование (слияние run'ов)
и разрывы строк.

Библиотека: `python-docx` (+ прямая работа с XML через `lxml` там, где
не хватает API).

---

## 2. Архитектурные решения

### 2.1 Продукт функции

```python
# src/stanok/engine/render.py
def render(fj: FillingJSON, template_path: Path) -> Document:
    """Подставить fields в шаблон, вернуть документ (не пишет на диск)."""
```

- Чистая функция: запись файла — дело `storage` (атомарно, с уникальными
  именами). Рендер возвращает объект документа.
- На входе — **только** валидный `FillingJSON` (см. спеку 002, FR-10).
  Сырые dict'ы не принимаются.

### 2.2 Слияние run'ов (run-merge)

Плейсхолдер `{{ поле }}` в Word часто разрезан проверкой орфографии
на несколько run'ов (`{{`, `по`, `ле`, `}}` с разным форматированием).
Алгоритм:
1. Собрать текст абзаца из всех run'ов, запомнить границы.
2. Найти плейсхолдеры `{{\s*имя\s*}}` в склеенном тексте.
3. Заменить: первый run диапазона получает весь новый текст
   (со своим форматированием), остальные run'ы диапазона очищаются.
4. Форматирование первого run'а сохраняется; разрывы строк (`\n`
   в значении → `w:br`) вставляются как разрывы, а не текст.

### 2.3 Что НЕ делает рендер

- Не читает Excel, PJ, файловую систему (кроме шаблона на входе).
- Не пишет результат на диск (возвращает `Document`).
- Не знает про счётчики/resume — всё уже разрешено в FJ.

## 3. Контракты

### 3.1 Входные данные

| Параметр        | Тип           | Описание                                |
|-----------------|---------------|-----------------------------------------|
| `fj`            | `FillingJSON` | Валидный filling (template/fields/dist) |
| `template_path` | `Path`        | `.docx`-шаблон с `{{ полями }}`         |

### 3.2 Выходные данные

`docx.Document` в памяти. Сохранение — через `storage`.

### 3.3 Ошибки

- `RenderError(SchemaError)` — базовый, с `path`/`errors`:
  - шаблон не docx / битый zip → `RenderError("template", [...])`;
  - поле шаблона отсутствует в `fields` → `RenderError("fields.<имя>", [...])`
    (строгий режим; молча пропускать плейсхолдеры запрещено);
  - незакрытый `{{` → `RenderError("template", [...])`.

## 4. Требования к реализации

| ID    | Требование                                                                                       | Приоритет  |
|-------|--------------------------------------------------------------------------------------------------|------------|
| REN-1 | Подстановка `{{ поле }}` с пробелами вокруг имени                                                | Must       |
| REN-2 | Run-merge: плейсхолдер из нескольких run'ов собирается и заменяется с сохранением форматирования | Must       |
| REN-3 | `\n` в значении → разрыв строки (`w:br`), не текст                                               | Must       |
| REN-4 | Неизвестное поле в шаблоне → `RenderError` (не молчание)                                         | Must       |
| REN-5 | Не писать на диск, вернуть `Document`                                                            | Must       |
| REN-6 | Никаких Qt/services/Home-путей (чистый engine)                                                   | Must       |
| REN-7 | Покрытие ≥ 90%                                                                                   | Must       |

## 5. Тестирование

Файл: `tests/engine/test_render.py`. Фикстуры: `tests/json/004-render/<кейс>/`
(`template.docx` + `filling.json` + `expected.docx`).

| Сценарий                      | Ожидаемое поведение                                               |
|-------------------------------|-------------------------------------------------------------------|
| Простая подстановка           | Текст заменён, форматирование (bold/italic) цело                  |
| Плейсхолдер разорван на run'ы | Собран и заменён, стиль первого run'а                             |
| `\n` в значении               | Разрыв строки в документе                                         |
| Неизвестное поле              | `RenderError` с именем поля                                       |
| Битый шаблон (не zip)         | `RenderError("template", ...)`                                    |
| Эталон побайтово              | `render(fj, template)` ≡ `expected.docx` по тексту абзацев/таблиц |

Сравнение эталона: по извлечённому тексту (абзацы + ячейки по порядку)
и форматированию ключевых run'ов — не побайтово (zip-метаданные docx
нестабильны).

## 7. Риски

| Риск                                                               | Митигация                                                            |
|--------------------------------------------------------------------|----------------------------------------------------------------------|
| `python-docx` не умеет часть XML (br в run'ах, клонирование строк) | Прямой `lxml` по `document.element`, слой `xmlops.py` изолирует хаки |
| Плейсхолдеры внутри колонтитулов/сносок                            | P0 — только body; остальное — отдельные FR позже                     |
| Нестабильность побайтового сравнения                               | Сравниваем текст+стили, не байты                                     |
