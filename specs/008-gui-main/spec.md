# Спецификация: 008-gui-main — Главное окно (NFR-3, FR-1)

**Статус:** Active
**Версия:** 0.1.0
**Фаза:** 2 (GUI)
**Зависит от:** 006-core-generate (generate_documents), 007-gui-strings (STRINGS), 005-core-storage (recent)
**FR:** FR-1, FR-2, FR-13
**NFR:** NFR-3

---

## 1. Назначение

Первое окно приложения: открыть существующий проект (папка или recent),
выбрать шаблон, запустить генерацию, увидеть прогресс и итог. Вся бизнес-логика
остаётся в `services`; окно только вызывает `generate_documents` в worker-потоке
и рисует результат. Все строки — через `STRINGS` (007).

FR-срез фичи: FR-1 (запуск генерации), выбор проекта/шаблонов как шаг FR-13
(создание/удаление — в 009), отображение полей — в 010.

---

## 2. Архитектурные решения

### 2.1 Состав

```
src/stanok/gui/
├── strings.py    # + новые ключи MAIN_* (007)
├── main_window.py  # MainWindow(QMainWindow): виджеты, сигналы (NEW)
└── worker.py       # GenerateWorker(QThread): прогон + сигналы (NEW)
```

- `MainWindow(store: ProjectStore | None = None)` — store инжектируется
  (тесты подсовывают tmp-Home; GUI по умолчанию — реальный `~/.stanok`).
- `GenerateWorker(cmd, store)` — выполняет `generate_documents` вне GUI-потока;
  сигналы: `progress(created, total)`, `finished(GenerateReport)`,
  `failed(str)`. Отмена — кооперативная (см. §2.3).
- Ошибки конфигурации (FR-10): `QMessageBox` с текстом исключения,
  окно живо, падения нет.
- `app.main`: без аргументов → `QApplication` + `MainWindow`;
  с `project_ref` → прежний CLI-режим (006, без регрессий).

### 2.2 Макет MainWindow

```
┌ Проект ───────────────────────────────┐
│ [Recent list]        [ Обзор... ]     │
│ Шаблон: [dropdown]   Источник: <label>│
│ [x] Продолжить (resume)  Лимит: [spin]│
│ [ Сгенерировать ]                     │
│ Статус: <statusbar>    Прогресс: [bar]│
└───────────────────────────────────────┘
```

- Recent list — `store.get_recent()` (папка + конфиг); выбор подставляет
  `project_ref`; «Обзор» — `QFileDialog` (папка проекта).
- Dropdown шаблонов — ключи `pj.templates`; перечитывается при смене проекта.
- Прогресс-бар: детерминированный при известном total, иначе busy-режим.
- Итог: `QMessageBox` «Готово: N, пропущено M, ошибок K»; кнопка «Показать»
  построчных ошибок (`report.errors`) — диалогу со списком.

### 2.3 Прогресс и отмена (срез 016)

Полноценные фоновые задания — в 016. Здесь минимум, чтобы GUI не висел:

- Прогон — в `GenerateWorker` (QThread), GUI-поток свободен.
- `generate_documents` принимает опциональный колбэк
  `progress(done: int, total: int) -> bool` (расширение 006, обратно совместимо):
  вызывается после каждого созданного документа; `True` = отменить.
- Отмена из прогресс-диалога взводит флаг; worker прерывает прогон между
  документами и возвращает частичный `GenerateReport` (созданное остаётся,
  курсор PJ сдвигается как в 006 §2.4).
- Без колбэка поведение 006 не меняется (CLI, тесты).

### 2.4 Зависимости и лицензия

- `pyproject.toml`: `PyQt5==5.15.11` (+ `PyQt5-Qt5==5.15.2` на win32 —
  у свежих сборок нет Windows-wheels) + `uv sync` (GUI уже заявлен как PyQt5/GPL
  в AGENTS.md — нового лицензионного решения не требуется).
- Тесты GUI — headless: `QT_QPA_PLATFORM=offscreen` (AGENTS.md).

## 4. Тестирование

Файл: `tests/gui/test_main_window.py` (`QT_QPA_PLATFORM=offscreen`,
фикстура проекта — `make_project` из `test_generate`).

| Сценарий                       | Ожидаемое поведение                       |
|--------------------------------|-------------------------------------------|
| Открытие окна с tmp-store      | recent-список заполнен, падения нет       |
| Выбор проекта из recent        | dropdown шаблонов = ключи PJ              |
| Прогон через worker (2 строки) | сигнал `finished`, 2 docx в `Результат/`  |
| Отмена посередине              | частичный отчёт, флаг `failed` не взведён |
| Битый проект (нет шаблона)     | `QMessageBox`, окно живо                  |
| CLI `run.py <папка>`           | прежний вывод, код 0 (регрессия 006)      |

## 5. Критерии приёмки

1. `QT_QPA_PLATFORM=offscreen pytest tests/gui/ -v` — зелёные.
2. `pytest tests/ -q` — все зелёные (включая AST-охранник с новыми ключами).
3. Ручной прогон: `python run.py` без аргументов открывает окно (Windows).
4. Pre-commit чистый, `CHANGELOG.md [Unreleased]` — запись о фиче 008.

## 6. Риски

| Риск                                 | Митигация                                                           |
|--------------------------------------|---------------------------------------------------------------------|
| PyQt5 нет в venv/CI                  | Зависимость в `pyproject` + `uv sync`; тесты только offscreen       |
| Гонки worker ↔ GUI                   | Worker не трогает виджеты — только сигналы; PJ пишет `ProjectStore` |
| Отмена роняет частично созданное     | Отката нет сознательно (006 §2.4); отчёт показывает созданное       |
| `progress`-колбэк расползается в API | Один опциональный параметр, CLI не меняется                         |
