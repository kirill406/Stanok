+# Спецификация: 013-multi-source — Несколько Excel-источников одного проекта

**Статус:** done
**Версия:** 0.1.0
**Фаза:** 3 (Пакетная генерация)
**Зависит от:** 006-core-generate (пайплайн одного источника), 012-batch-resume (limit, курсор, resumed_from)
**FR:** FR-7
**NFR:** NFR-4

## 1. Цель

Проект хранит N записей `data_sources` (схема уже позволяет), но прогон обрабатывает
только один источник: без `data_source` — первый с warning, по имени — с неверными
mode/start при индексе > 0 (resolve читает `data_sources[0]`). FR-7 требует:
`data_source=None` — прогон по **всем** источникам по порядку; выбор по имени — корректный
прогон именно этого источника.

## 2. Контракт

### 2.1 Поведение `generate_documents`

| `cmd.data_source`  | Поведение                                                  |
|--------------------|------------------------------------------------------------|
| `None`             | Источники по порядку PJ. Warning «using first» удаляется.  |
| имя файла          | Только этот источник (индекс любой; mode/start_row — его). |

Прогон одного источника — текущий пайплайн без изменений
(окно чистых строк → `resolve_rows(..., limit=max_docs)` → render → `Результат/`).
`max_docs` — лимит **на источник**, не на прогон (документировать в 006).

### 2.2 Общее состояние прогона

- Счётчики сквозные: источник k+1 продолжает нумерацию источника k
  (один `counters` на прогон, единый `save` в конце).
- Курсор свой у каждого источника: `data_sources[i].start_row` по правилам 012
  (sequential +окно, circular +круг, constant +1).
- Отчёт агрегирует `created/skipped/errors/output_paths/elapsed`.
- `resumed_from` — курсор **первого** обработанного источника
  (`None` при старте с 0). Правило 012 без изменений, область — первый источник.
- Ошибки строк помечаются источником: сообщение `"файл: <msg>"`
  (формат кортежа `(row_index, msg)` не меняется).

### 2.3 Изоляция источника в resolve

`resolve_rows` не меняется. Сервис на каждый источник строит рабочую копию
с **одним** источником (`work.data_sources = [ds]`, `start_row = 0`),
тем самым убирая расхождение «выбран N-й, резолвится 1-й».

### 2.4 GUI (окна 1–3)

- Окно 2: комбобокс источников (позиции — файлы из PJ, по умолчанию «все»);
  выбор прокидывается в `GenerateCommand.data_source`.
- Окно 1 «генерировать всё»: `data_source=None` (все источники всех проектов).
- Окно 3 без изменений (константы не зависят от источника).

### 2.5 CLI

`python run.py <проект>` — все источники; опция `--source <файл>` — один источник
(флаг новый; без него поведение меняется с «первый» на «все» — задокументировать).

## 3. Ошибки

- Пустой `data_sources` — как сейчас (`TemplateError`, выбор невозможен).
- Имя не найдено — как сейчас (`data source not found`).
- Битый второй/третий xlsx — прогон продолжается по остальным источникам,
  ошибка файла — строкой отчёта с индексом `-1` и именем файла.

## 4. Тесты (NFR-4)

`tests/services/test_generate.py`:
- два источника sequential: created = сумма, счётчик сквозной, оба курсора;
- `data_source=<второй>` чинит mode/start второго (регрессия на расхождение);
- circular вторым + `max_docs`: 2 строки × 5, курсор второго = +круг, первого untouched;
- битый второй файл: первый сгенерирован, ошибка с именем файла в отчёте;
- `resumed_from` — курсор первого источника.

## 5. Вне скоупа

- Несколько шаблонов за прогон (отдельный FR; warning «using first» остаётся).
- Параллельные прогоны источников (последовательно; GUI-прогресс суммирует).
- Объединение/дедуп строк между источниками.
