# Спецификация: 015-project-manage — Управление проектом (FR-13)

**Статус:** Active
**Версия:** 0.1.0
**Фаза:** 4 (Управление проектами)
**Зависит от:** 005-core-storage (save/delete/recent), 009-gui-project (таблица шаблонов),
  014-project-create (`_place_source`, скан плейсхолдеров)
**FR:** FR-13
**NFR:** NFR-3, NFR-4

## 1. Цель

Проект нельзя изменить после создания: ни добавить шаблон, ни удалить лишний,
ни снести проект. FR-13 закрывает весь цикл управления. Точки входа — окно 2
(шаблоны) и окно 2 (удаление проекта); окно 1 не меняется.

## 2. Контракт

### 2.1 Сервис (`ProjectStore`, всё через ref → PJ в Home → `save`)

```python
def add_template(self, ref, docx: Path, copy_files: bool = True) -> str:
    """Прикрепить docx: копия в Шаблоны/ (уникализация, 014), fields из
    плейсхолдеров 1:1 в table, имя — stem с суффиксом при коллизии. Возврат: имя."""

def remove_template(self, ref, name: str) -> None:
    """Убрать шаблон; последний удалять запрещено (StorageError)."""

def delete_project(self, ref, delete_folder: bool = False) -> None:
    """Снос: конфиг (+`.bak`) из Home, запись из recent; при флаге — папка
    целиком (`shutil.rmtree`, ignore_errors=False с понятной ошибкой)."""

def remove_recent(self, folder: str, config: str) -> None:
    """Убрать запись из recent (нужен удалению; 005 дал только add)."""
```

Ошибки — `StorageError`; PJ после каждой операции валиден (`validate_pj`
внутри `save` неявно через типы; удаление последнего шаблона блокируется до записи).

### 2.2 Окно 2

- Кнопка «Добавить шаблон» над таблицей: picker `.docx` → `add_template(ref, copy)`,
  где copy = инверсия «файл уже в Шаблоны/»? Решение: как в окне 4 — копировать,
  если файл снаружи; если внутри — связать (авто, без чекбокса; окно 2 — быстрый флоу).
- Колонка «Удалить» у каждой строки таблицы (кнопка; confirm только для непустого?
  Решение: confirm всегда — удаление необратимо для fields-маппинга).
- Кнопка «Удалить проект» внизу (красная): confirm-диалог с именем проекта
  + чекбокс «удалить папку с файлами» → `delete_project` → закрыть окно 2.
- После add/remove — перестроить таблицу и комбобокс источников не трогаем
  (источники — вне скоупа).

### 2.3 Строки (STRINGS, NFR-3)

`TPL_ADD`, `TPL_REMOVE`, `TPL_REMOVE_ASK`, `TPL_LAST_KEPT`, `PROJ_DELETE`,
`PROJ_DELETE_ASK`, `PROJ_DELETE_FOLDER`, `PROJ_DELETED` + заголовки ошибок.
Сервисные тексты — английские `StorageError` как в 005/014 (показ raw в диалоге).

## 3. Ошибки

- Последний шаблон — запрет с объяснением (проект без шаблонов негенерируем).
- Удаление проекта с открытой генерацией: блокировать кнопкой (`_running`, как прогон).
- `rmtree` упал midway — конфиг уже снесён: сообщить, что папка удалена частично.
- Папка уже удалена вручную — `delete_folder` не ошибка (missing → ok).

## 4. Тесты (NFR-4)

Сервис: attach (копия + fields), attach связью изнутри, дубли стемов,
запрет последнего, снос конфига + recent чист, снос с папкой, missing-папка ok.
GUI offscreen: кнопки добавляют/убирают строки таблицы; удаление проекта
закрывает окно 2 (fake `delete_project` + accept-confirm через monkeypatch).

## 5. Вне скоупа

- Добавление/удаление Excel-источников (отдельная спека).
- Переименование проекта/шаблона.
- Удаление из окна 1 (только через окно 2 — одна точка опасности).
- Undo/корзина (снесённое не восстановить; confirm — единственная защита).
