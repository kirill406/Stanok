# Спецификация: 016-error-dialogs — Битые входы → диалог (FR-10)

**Статус:** done
**Версия:** 0.1.0
**Фаза:** 5 (Надёжность)
**Зависит от:** 008-gui-main, 009-gui-project, 010-gui-fields (все слоты окон)
**FR:** FR-10
**NFR:** NFR-3, NFR-5

## 1. Цель

Аудит слотов GUI на битые входы показал две незакрытые точки: открытие окна 3
при битом конфиге/пропавшем шаблоне и перезагрузка таблицы окна 2 при битом
конфиге — обе роняют окно исключением. FR-10: везде диалог, нигде падения.
Граница: конструкторы диалогов вправе бросать (их ловят вызывающие окна);
слоты — никогда.

## 2. Контракт

### 2.1 Матрица (аудит 016)

| Точка | Вход | Статус |
|-------|------|--------|
| Окно 1: обзор/строка/очередь | битый конфиг, нет папки | ✅ диалог (`_show_error`, очередь) |
| Окно 2: конструктор | битый конфиг | ✅ бросает → ловит окно 1 |
| Окно 2: прогон | битый xlsx/шаблон | ✅ `failed` → диалог |
| Окно 2: шаблоны/создание | ошибки сервиса | ✅ warning в диалоге |
| Окно 2: `_open_fields_dialog` | битый конфиг, нет шаблона | ❌ чинить: warning, окно 2 живо |
| Окно 2: `_reload_templates` | битый конфиг mid-session | ❌ чинить: warning, старые строки живы |
| Окно 3: save/dirty | ошибки записи | ✅ critical в диалоге |
| Окно 4: создать | любые ошибки сервиса | ✅ warning в диалоге |
| CLI | любые ошибки | ✅ лог + код 1 |

### 2.2 Исправления

- `_open_fields_dialog`: try вокруг конструктора + `exec_`; исключение →
  `logger.warning(..., exc_info=True)` + `QMessageBox.warning(MAIN_ERROR_TITLE)`.
- `_reload_templates`: try вокруг `resolve_project`; исключение → warning
  + старые строки таблицы остаются (окно живо, §5.3 spec.md).
- Новых строк STRINGS не требуется (заголовок `MAIN_ERROR_TITLE` уже есть).

## 3. Тесты (NFR-4)

- Окно 3 при пропавшем шаблоне: удалить шаблон из конфига → открыть окно 3
  → warning, исключения нет.
- Окно 2 при битом конфиге mid-session: испортить Home-конфиг после открытия →
  `_reload_templates` → warning, строки на месте.
- Регрессия: существующие тесты окон зелёные без изменений.
