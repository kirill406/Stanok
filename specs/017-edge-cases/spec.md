# Спецификация: 017-edge-cases — Граничные случаи (FR-14, §5.3)

**Статус:** done
**Версия:** 0.1.0
**Фаза:** 5 (Надёжность)
**Зависит от:** 005-core-storage (resolve/migrate), 008-gui-main (обзор)
**FR:** FR-14
**NFR:** NFR-3, NFR-4

## 1. Цель

Три грани из spec.md §5.3/§9.1 без покрытия: папка без конфига (FR-14 —
сейчас сырой английский текст сервиса), коллизия имени при миграции
(молчаливая перезапись конфига в Home + снос legacy = потеря данных),
протухшие файлы после открытия окон (поведение есть, тестов нет).

## 2. Контракт

### 2.1 FR-14: понятная ошибка

- Окно 1 `_on_browse`: `StorageError` с `path == "resolve"` маппится
  на `STRINGS.MAIN_NO_PROJECT` («В папке нет проекта: нет project.stanok
  и конфига в Home») + путь папки. Остальные ошибки — как раньше (raw).
- CLI без изменений (лог + код 1; дружелюбие — прерогатива GUI).

### 2.2 Коллизия при миграции (§5.3: `(1)`, `(2)`, существующий не трогаем)

- `migrate_from_project`: имя `folder.name` занято в Home → суффиксы
  `«имя (1)»`, `«имя (2)»`, …; существующий конфиг не перезаписывается,
  legacy сносится только после успешной записи.
- Хелпер `ProjectStore._unique_config_name(base) -> str`.

### 2.3 Протухшие файлы (тестовое закрепление)

- Удаление docx после открытия окна 2 → прогон → диалог ошибки, без исключения.
- Удаление xlsx → то же (окно 3 при этом показывает пустое превью — уже так).

## 3. Тесты (NFR-4)

- Обзор пустой папки → `MAIN_NO_PROJECT` в критическом диалоге.
- Миграция при занятом имени → `proj (1).stanok`, оба конфига живы.
- Прогон с удалёнными docx/xlsx → `failed`-диалог, исключений нет.

## 4. Вне скоупа

- Русские тексты остальных сервисных ошибок (прецедент raw).
- FR-8 сверх реализованного (именованные конфиги/резолвер — 005).
