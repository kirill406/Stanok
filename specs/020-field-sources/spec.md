# Спецификация: 020-field-sources — Смена источника поля в окне 3 (FR-2)

**Статус:** Active
**Версия:** 0.1.0
**Фаза:** 7 (GUI-поля)
**Зависит от:** 010-gui-fields (таблица полей, Save, dirty-чек)
**FR:** FR-2
**NFR:** NFR-3, NFR-4

## 1. Цель

Окно 3 показывает источник поля readonly-текстом: тип сменить нельзя,
значение правится только у констант. FR-2 требует полного заполнения полей
через GUI — значит, и смену типа источника, и правку значения под каждый тип.
После 020 окно 3 — полный редактор полей шаблона.

## 2. Контракт

### 2.1 Колонка «Источник» — комбобокс

Позиции — существующие `FLD_SRC_*` (`константа/таблица/счётчик/сегодня`),
`currentData` — имя `FieldSource`. Смена позиции:
перестраивает ячейку значения под новый тип, ставит dirty-флаг.

### 2.2 Ячейки по типу

Колонки таблицы: Поле | Источник | Данные | Значение. «Данные» — редакторы
по типу ниже; «Значение» — нередактируемый итог (что попадёт в документ).

| Тип      | Редактор                                                  | Preview/поведение                                             |
|----------|-----------------------------------------------------------|---------------------------------------------------------------|
| constant | QLineEdit (как сейчас)                                    | редактируемый текст; при смене типа предзаполняется `{{Имя}}` |
| table    | Два нередактируемых комбобокса: файл источника → колонка  | нередактируемая строка: значение выбранной колонки в первой строке; до выбора — первый столбец |
| counter  | Комбобокс имени + ширина (1/01/001/0001) + правка текущего | число с паддингом под ширину                                  |
| today («Дата») | Селектор формата даты (см. §2.5)                    | дата в выбранном формате                                      |

### 2.3 Счётчики — только числа

- Таблица счётчиков под таблицей полей: Название | Привязка | Текущее значение;
  кнопка «Создать» (промпт имени; дубликат — warning). Пункт «+ Новый…»
  из комбобоксов удалён.
- Привязка: файл источника или «отсутствует» (`CounterDef.table`, `None` —
  считает везде). Привязанный счётчик в чужом прогоне не растёт, поле —
  пусто (симметрично §7); движок знает текущий источник из рабочей копии.
- Ширина — `1/01/001/0001` (длина результирующей строки, паддинг нулями);
  хранится в `CounterDef.format`; действует на все поля счётчика.
- Текущее значение (`last`) правится и в строках полей, и в таблице;
  нецелое/отрицательное — блок Save (§3); пишут только тронутые строки,
  таблица — второй (побеждает при конфликте).
- Висячая ссылка (имени нет в `counters`) показывается как есть и
  воскрешается при Save; plain/month из GUI убраны полностью; движок старые
  значения понимает (legacy: month — как раньше, plain — как `1`).

### 2.4 Заголовки колонок (table)

- Схема: `FieldDef.table: str | None = None` — файл источника колонки
  (относительный путь как в `data_sources`); `None` — legacy (любой источник).
  Миграция не нужна (дефолт). Движок не меняется: резолв по имени колонки
  как сейчас; привязка — для GUI и будущих проверок.
- Комбобокс файла: только файлы из `pj.data_sources` («Любой» убран —
  давал ошибку); legacy-`None` при открытии встаёт на первый источник
  и записывается им при ближайшем Save.
  Смена файла перестраивает комбобокс колонок заголовками этого файла
  (читаются только заголовки; битый файл — пустой список, с предупреждением).
- Оба комбобокса нередактируемые: только выбор существующих, свободного ввода нет.
  Хранимое значение отсутствует в списке (колонку удалили из xlsx) —
  комбобокс пуст; Save блокируется правилом пустого значения (§3).

### 2.5 Формат даты («Дата» вместо «Сегодня»)

- Подпись типа — `Дата` (`FLD_SRC_TODAY` переименовано значением, ключ тот же).
- Формат хранится в `FieldDef.value` (ранее всегда `None`): ключи `dmy`
  (`16.10.2026`), `day` (`16`), `month_ru` (`октября`),
  `month_num` (`10`), `year` (`2026`), `ru_long` (`16 октября 2026`;
  месяцы родительным падежом вручную — без зависимости от локали ОС).
- `value=None` (legacy) — движок отдаёт объект `date` как раньше; пункт
  «Как в проекте» есть только у таких полей; новые поля его не получают
  (сразу `dmy`); пустой формат блокирует Save (§3).

### 2.6 Раскладка

Колонка «Значение» — `Stretch` до конца окна (`QHeaderView`), остальные —
по содержимому.

Примечание по слоям: русские названия месяцев живут в `STRINGS`
(того требует AST-охранник NFR-3), движок импортирует их оттуда —
прецедент `engine/schema.py` → `gui/strings.py`, нарушение правила
gui → services → engine зафиксировано сознательно.

### 2.7 Save / dirty — без изменений

Кнопка «Сохранить», dirty-чек Save/Discard/Cancel, запись через `store.save`
(010). Смена типа — тоже dirty (даже если значение не трогали).

### 2.9 Шаблон имени файла

Строка «Имя файла:» под таблицей счётчиков — `filename_template` проекта
(общий, не на шаблон); правится текстом, пустое блокирует Save.
Кнопка «Вставить поле» — меню: поля шаблона + `{i}` + `{template}`,
вставка плейсхолдера в курсор. Дефолт новых проектов — имя проекта (014).

### 2.8 Строки (NFR-3)

`FLD_CNT_NAME` / `FLD_CNT_BIND` / `FLD_CNT_LAST` (таблица счётчиков),
`FLD_NONE` («отсутствует»), `FLD_COUNTER_CREATE` («Создать»),
`FLD_COUNTER_NAME` (промпт имени), `FLD_DUP_COUNTER`, `FLD_CNT_BAD`,
`FLD_DATE_KEEP` («как в проекте» для legacy-`None`),
`FLD_DATE_DMY` / `FLD_DATE_DAY` / `FLD_DATE_MONTH` / `FLD_DATE_MONTHNUM` /
`FLD_DATE_YEAR` / `FLD_DATE_RU` (подписи пресетов),
`FLD_BAD_VALUE` («не целое число» для `last`); `FLD_SRC_TODAY` = `Дата`.
`FLD_FMT_PLAIN` / `FLD_FMT_MONTH` удаляются (заменены шириной).

## 3. Ошибки

- Пустое значение колонки при Save — `QMessageBox.warning` в диалоге,
  запись блокируется (какое поле — в тексте). Сюда же: колонка из списка пропала
  (комбобокс пуст) — тот же warning.
- `last` не целое ≥ 0 — тот же warning (`FLD_BAD_VALUE`).
- Невалидный PJ после правки — как сейчас (critical + лог, 010/016).

## 4. Тесты (NFR-4)

Offscreen (`test_fields_dialog.py`): смена table→constant + Save → PJ обновлён,
значение предзаполнено `{{Имя}}`; table с файлом+колонкой пишется в PJ
(`value` + `table`) + виден value-лейбл первой строки; legacy-поле без `table`
открывается (`None`); кнопка «Создать» заводит счётчик (+дубликат — warning);
привязка пишется в `CounterDef.table`; чужой счётчик в чужом прогоне — пусто;
ширина `001` даёт `043`;
формат даты `month_ru` → `октябрь`; today-legacy (`None`) → объект date;
комбобокс колонок содержит заголовки выбранного файла;
пропавшая колонка → пусто + блок Save; пустое/`last`-мусор → warning;
dirty после одной смены типа.

## 5. Вне скоупа

- Добавление/удаление самих полей (только смена источника существующих).
- Проверка на уровне движка (там fail-fast построчно остаётся);
  сервисный pre-flight — в скоупе (§7).

## 7. Pre-flight колонок (generate)

- Перед resolve каждого источника: table-поля сверяются с заголовками
  ТЕКУЩЕГО источника (resolve читает только его — привязка значения не имеет);
  нет колонки → `TemplateError` `поле 'X': колонка 'Y' не найдена в <файл>`
  до создания документов. Объединение ключей строк (защита от рваных строк).
- Поле, привязанное к другому файлу, в чужом прогоне не проверяется
  и резолвится в `None` (рендер — пусто): документы по остальным источникам
  генерируются, опечатки в своих колонках по-прежнему ловятся.
## 6. Синхронизация полей при открытии окна 2

- `ProjectStore.sync_template_fields(ref)`: сверка плейсхолдеров docx
  с полями PJ по каждому шаблону; новые → table-поля 1:1; удалённые
  из docx в PJ остаются (маппинги не трогаем); битые/missing файлы —
  пропуск с warning в лог; возврат `{шаблон: [добавленные]}`.
- Окно 2 зовёт sync в конструкторе до построения таблицы (окно 3 после
  этого всегда видит актуальный список).

## 8. Колонтитулы

- `xmlops.iter_paragraphs(doc, headers=True)`: тело + вложенные таблицы +
  header/footer (+first/even при включённых настройках секции);
  связанные с предыдущим разделом пропускаются (без двойной подстановки).
- Рендер и скан используют его же: плейсхолдеры в колонтитулах подставляются
  и попадают в окно 3 через sync; строгий режим действует и там.

## 9. Удаление из недавних (окно 1)

- Кнопка «Убрать» в строке recent: `remove_recent` + обновление списка.
  Убирает только запись (проект и конфиг целы, вернуть — через «Открыть проект»).

## 10. Источники в окне 2

- Подпись «Источники:», кнопка «Добавить источник...»: picker xlsx →
  `ProjectStore.add_source` (копия в `Данные/` с уникализацией, sequential,
  дубликат — ошибка) → комбобокс перестраивается с выбором нового.
- Удаления источника нет (вне скоупа).

## 11. Идентичность проекта: config + папка в PJ

- `ProjectJSON.folder: str | None` — абсолютный путь папки с данными;
  `init_project` пишет его, `migrate_from_project` тоже. GUI ходит по имени
  конфига, папку берёт через `project_folder` (PJ → dir-ref → recent).
- `resolve_project`: dir-ref самолечит `folder` (`_remember_folder`); config,
  которого нет в Home, но есть в recent, резолвится по запомненной папке
  (legacy-фолбэк для миграции). Убрана нечёткая привязка по имени папки.

## 12. Открытие проекта (окно 1)

- Кнопка «Открыть проект» открывает список известных проектов
  (`list_named`: имя + папка) → выбор по config (`touch_recent` + окно 2).
- Recent-строки несут config (не папку): клик/генерация/«все» — по config.
- Пропавшая папка проекта: диалог «указать новую папку» →
  `set_project_folder` (перепривязка + recent) и повторное открытие.

## 13. Валидация создания (окно 4)

- Предпросмотр итогового пути `папка/имя` (обновляется на ввод).
- Имя занято (`config_exists`) или папка `Данные`/`Шаблоны` — красная
  подсказка + кнопка «Создать» выключена (сервис тоже отвергает).
- Несуществующая папка — вопрос «Создать её?»; отказ прерывает создание.
- После успеха окно 1 открывает окно 2 по имени config.
