# Спецификация: 021-counters — Счётчики на источники, композиция из нескольких источников, default_template

**Статус:** done
**Версия:** 0.1.0
**Фаза:** 7 (GUI)
**Зависит от:** 020-field-sources (окна 2/3, CounterDef.table, идентичность по config)
**FR:** FR-2, FR-4, FR-5, FR-7, FR-12, FR-13, FR-17
**NFR:** NFR-3, NFR-4

## 1. Цель

Убрать неявные параметры генерации (место запуска, выбор источника в окне 2)
и собрать модель вокруг явных привязок:

- один документ собирается **из нескольких источников одновременно** согласно
  типу (`mode`) каждого;
- у каждого источника есть привязанные счётчики; table-поле ссылается на
  счётчик, а счётчик — на источник и одну позицию;
- явный `default_template` для запуска из окна 1.

Итог: результат генерации зависит только от конфига PJ, а не от того, из какого
окна и что было выбрано.

> **Смена вывода и отсутствие миграции.** Формат PJ меняется ломающе.
> Пользователей нет, поэтому бампа версии формата не делаем (осознанный
> разрыв, см. `specs/spec.md` §9.1). Для совместимости `last`/`start_row`
> при загрузке сводятся в `pos`; других миграций нет.

## 2. Контракт

### 2.1 Схема PJ

```
ProjectJSON:     version, templates, data_sources, counters,
                 filename_template, folder,
                 default_template: str
DataSourceDef:   file: str, mode: "sequential"|"circular"|"constant"
                 # позиция (pos) — на счётчике
TemplateDef:     file: str, fields: {name: FieldDef}, limit: int = 0
CounterDef:      pos: int = 0, format: str = "1",
                 table: str|None = None,      # привязка к источнику
                 resume: int = 1              # 1 — pos сохраняется; 0 — сброс
FieldDef:        source, value,
                 counter_name: str|None = None  # TABLE: обязателен; поле `table` УБРАНО
```

- `default_template` валидируется как существующий ключ `templates`;
  при отсутствии (конструктор) — первый шаблон.
- `TemplateDef.limit` — лимит на шаблон; `0` = без лимита.
- `CounterDef.table` — источник строки (для table-полей) либо `None`
  (числовой счётчик, не участвует в композиции).
- `CounterDef.pos` — **одна позиция**: и строка источника, и печатаемое число.
  Строка first-row берётся с нуля, поэтому номер первого документа равен `pos`.
  После прогона при `resume=1` пишется сдвинутое значение, при `resume=0` —
  остаётся; для режима `constant` не меняется никогда.
- Table-поле ссылается на счётчик через `counter_name`; источник берётся из
  `counters[counter_name].table`.
- При загрузке старого PJ поля `last`/`start_row` сводятся в `pos`
  (`start_row` при `table`, иначе `last`); версия формата не меняется.

### 2.2 Композиция документа (движок)

- **Участвующие источники** — множество `counter.table` (без `None`) среди
  счётчиков, на которые ссылаются table-поля данного шаблона.
- Порядок `data_sources` не влияет ни на что (только отображение).
- **Число документов `N`:**
  - `limit = template.limit` (0 → ∞);
  - `seq = min(доступные строки) по участвующим источникам с mode=sequential`,
    где доступные строки = `max(0, len(rows) − pos(счётчика))`;
  - если sequential есть: `N = min(seq, limit)`;
  - иначе если `limit > 0`: `N = limit`;
  - иначе если circular есть: ровно один круг, `N = min(len(rows)) по circular`;
  - иначе (только constant): `N = 1`.
- **Строка источника для документа `k = 0..N−1`** (позиция счётчика = `pos`):
  - `sequential`: `pos + k`;
  - `circular`: `(pos + k) mod len(rows)`;
  - `constant`: `pos` (позиция не двигается).
- **Пустые строки больше не пропускаются.** Если ячейка строки пуста — поле
  пустое, документ создаётся; остальные поля берутся. `_is_empty_row`-пропуск
  и `GenerateReport.skipped` удаляются.
- В одном документе в строку подставляются значения из разных источников
  (по их строкам); значение table-поля = ячейка `value` этой строки.
- **Счётчики:** значение counter-поля = `pos + k` (`pos` для `constant`);
  одно значение на документ для всех полей этого счётчика. Число печатается
  `format`-ом. Единицы не добавляется: первый документ печатает `pos`.
- После прогона по каждому счётчику с источником: `resume=1` → `pos += processed`
  (sequential и circular; строка при чтении берётся по модулю, поэтому число
  растёт), `constant` и `resume=0` → без изменений. Числовой счётчик (`table=None`)
  продолжает нумерацию всегда: `pos += processed`. Значения персистятся, если был
  хотя бы один обработанный документ (`processed > 0`), даже когда все документы
  завершились ошибкой.

### 2.3 Валидации PJ

- `default_template ∈ templates` (иначе ошибка валидации).
- Table-поле: `counter_name` обязателен и должен существовать в `counters`.
- Counter-поле (`source=counter`): `value` обязателен и должен существовать в
  `counters` (иначе ошибка валидации).
- Счётчик table-поля обязан быть привязан к источнику
  (`counters[counter_name].table is not None`), иначе ошибка.
- `counter.table` обязан быть в `data_sources[*].file`.
- «Не менее одного счётчика на источник»: каждый `DataSourceDef` должен иметь
  ≥1 счётчик с `table == file`; иначе ошибка валидации.

### 2.4 Авто-создание счётчиков

- При `init_project` (источники, найденные в `Данные/`) и при `add_source` —
  для каждого источника создаётся счётчик: `table = file`, `pos = 0`,
  `resume = 1`, `format = "1"`.
- Имя счётчика — из имени файла без расширения; при коллизии — суффикс `_2`,
  `_3`, … (`data`, `data_2`). Переименование источника **не** меняет имя
  счётчика.
- Удаление источника **оставляет** его счётчики (пользователь удаляет сам).

### 2.5 Окно 1 (запуск)

- Запуск (`Прогон`, «Все») генерирует `default_template` — все участвующие
  источники одновременно.
- В строке каждого проекта перед кнопкой «Сгенерировать» показаны имя
  `default_template` и его лимит; лимит редактируется на месте и сразу
  сохраняется в PJ (`TemplateDef.limit`, `0` — без лимита).
- Лимит остаётся свойством шаблона: то же значение правится в окне 2
  (в строке шаблона); окно 1 запускает `default_template` с сохранённым лимитом.
- Неиспользуемые строки окна 1 (`MAIN_TEMPLATE`, `MAIN_SOURCE`,
  `MAIN_RESUME`, `MAIN_LIMIT`) удаляются.

### 2.6 Окно 2 (проект)

- Убрать нередактируемую строку «данные» (путь, `PROJ_DATA`) и комбобокс
  выбора источника (`PROJ_SOURCE`); таблица источников получает свою подпись.
- Кнопки «Добавить шаблон» и «Добавить источник» переносятся вниз,
  перед «Удалить проект».
- Добавить кнопку «Настройки проекта».
- **Таблица источников:** `файл (ro) | тип (mode, комбо sequential/circular/constant)`
  — редактируемая; под таблицей — пояснение типов (`STRINGS.PROJ_SRC_TYPES_HINT`).
- **Таблица шаблонов:** колонки в порядке «Шаблон | По умолчанию | Лимит |
  Сгенерировать | Редактировать | Убрать». Клик по названию больше не открывает
  окно 3: для этого есть кнопка «Редактировать» (`PROJ_EDIT`). «Сгенерировать» —
  прогон со своим лимитом (из `TemplateDef.limit`, сохраняется), радио
  «По умолчанию» — единственный выбор → `default_template`.
- **Подсказка после создания проекта:** окно 2 открывается с `highlight_new=True`;
  комбобоксы типов источников и кнопки «Редактировать» плавно пульсируют зелёным
  (`gui/blink.py`, `GreenBlink`). Пульс источника прекращается после смены типа,
  пульс кнопки — после открытия окна 3; при закрытии окна 2 все пульсы
  останавливаются. При обычном открытии проекта подсказок нет.
- Удаление шаблона, который является `default_template`, запрещено:
  предупреждение «Смените шаблон по умолчанию» (плюс действующее правило
  «последний шаблон не удалять»).

### 2.7 Настройки проекта = окно создания

- Одно окно (`create_dialog`) в двух режимах: создание (поля пустые) и
  редактирование настроек (поля заполнены текущими значениями).
- Поля: имя конфига, папка, `default_template`. Папки `Данные/Шаблоны/Результат`
  из настроек убраны.
- В режиме создания «папка» — базовая: проект создаётся в `<папка>/<имя>`,
  внутри — `Данные/`, `Шаблоны/`, `Результат/`. Предпросмотр «Файлы проекта»
  показывает абсолютный путь проекта и три подпапки отдельными строками; тот же
  вид — в настройках проекта (окно 4), где базой служит сама папка проекта.
- Перед созданием: если `<папка>/<имя>` не существует — спросить «Создать?»;
  отказ возвращает к редактированию окна (без создания).

### 2.8 Окно 3 (шаблон)

- Строка «Имя файла:» переносится наверх окна.
- **Таблица счётчиков**: колонки
  `название | источник данных (table) | формат (format) | позиция (pos) |
  начинать заново (resume)`.
  У колонок — подсказки (tooltip), под таблицей — пояснение: «Позиция» — это
  и строка источника, и печатаемое число.
  - `resume` — чекбокс в строке счётчика; недоступен для числового счётчика и
    режима `constant` (позиция там не меняется).
  - `pos` редактируется с предупреждением: «это позиция, генерация её двигает».
  - Источник с режимом `constant` («Одна строка»): «Позиция» только для чтения —
    строка фиксирована, число не растёт.
  - Изменение «Позиции» сразу обновляет предпросмотр в таблице полей у всех
    counter-полей и table-полей этого счётчика (у table-поля — значение ячейки
    строки `pos`).
  - Рядом с «Позицией» — кнопка с глазом «Выбрать данные»: открывает выбор
    строки из привязанной таблицы и записывает её 0-базовый номер в `pos`.
    Кнопка недоступна, если источник не привязан или вариант выбора не
    реализован в сборке.
  - Вариант 1: окно показывает всю таблицу сеткой; пользователь выбирает строку
    целиком (колонка «Строка» — 0-базовый номер строки данных), и в `pos`
    записывается номер выбранной строки; двойной клик подтверждает выбор.
    Автоподстановки текущего значения нет: «Выбрать» активна только после
    явного выбора строки, под таблицей показано «Будет записано: N».
- Table-поле: вместо комбобокса файла — комбобокс счётчика (`counter_name`),
  определяющий источник; второй комбобокс — колонка (заголовки файла источника).
- Создание счётчика в окне 3 допустимо; окно 1 чекбокса `resume` не имеет.

### 2.9 Строки (NFR-3)

Новые ключи `STRINGS`: подписи колонок таблицы счётчиков («источник данных»,
«позиция», «формат», «начинать заново»), подсказки к ним, «Выбрать данные»,
«Смените шаблон по умолчанию», кнопка «Настройки проекта», подписи режимов
(sequential/circular/constant). Удаляемые: комбобокс `PROJ_SOURCE`, `PROJ_DATA`,
`APP_RESUME_HELP`, `MAIN_RESUME`, поля отчёта про `skipped`.

## 3. Ошибки

- Нарушение §2.3 — `PJValidationError` при загрузке PJ (диалог, окно живо).
- Несовпадение колонки с источником счётчика — pre-flight `TemplateError`
  до создания документов (проверка по источнику каждого table-поля).
- Нечитаемый источник при одновременном прогоне — fail-fast `TemplateError`
  до создания документов (без источника композиция невозможна), как и
  несовпадение колонки.
- Пропавший файл источника в окне 3: однократное предложение —
  «выбрать папку с источником» (файл находится по имени в выбранной папке и
  копируется в проект либо привязывается относительным путём) или «создать
  папку» (`Данные`/`Шаблоны`); далее — обычное предупреждение (один раз на
  источник).

## 4. Тесты (NFR-4)

- **schema:** `default_template` (валид/невалид), table-поле без `counter_name`,
  несуществующий `counter_name`, counter-поле со ссылкой на несуществующий
  счётчик, счётчик без `table` у table-поля,
  `counter.table ∉ data_sources`, источник без счётчиков; `pos`/`resume`
  дефолты и сведение legacy `last`/`start_row`.
- **resolve:** композиция 2+ источников; `N` = limit / min(sequential) /
  один круг (все circular) / 1 (только constant); строка по `mode`
  (sequential/circular/constant); номер = `pos + k` без единицы; `constant`
  печатает и берёт одну и ту же `pos`; пустая ячейка → пустое поле, документ есть.
- **generate:** одновременный прогон всех участвующих источников; `pos`
  по `resume=1/0`; авто-счётчики при `init_project`/`add_source`; коллизия
  имени (`data_2`); один сдвиг счётчика на документ (два поля — один);
  circular хранит абсолютный счёт (без модуля); `constant` не меняется;
  отсутствие `skipped`; `default_template` при запуске из окна 1.
- **GUI окно 2:** нет строки пути/комбобокса источников; кнопки внизу;
  «Настройки проекта»; таблица источников (тип редактируется); радио
  `default_template`; запрет удаления default.
- **GUI окно 3:** «Имя файла» наверху; таблица счётчиков с новыми колонками;
  чекбокс `resume` per-counter; table-поле выбирает счётчик и колонку;
  пропавший источник — предложение выбрать папку/создать папку (однократно).
- **GUI окно создания/настроек:** одно окно, два режима, `default_template`;
  проект создаётся в `<папка>/<имя>` (Данные/Шаблоны/Результат);
  предпросмотр — абсолютные пути; отсутствие папки проекта спрашивает «Создать?».

## 5. Вне скоупа

- Полноценные миграции старых PJ и смена версии формата (единственное —
  `last`/`start_row` сводятся в `pos` при загрузке).
- Редактирование имени/порядка источников; удаление источника (пока нет).
- Слияние `counters` в `data_sources` (счётчики остаются именованными).
