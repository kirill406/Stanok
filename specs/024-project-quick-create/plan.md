# План: 024-project-quick-create

Спецификация: [spec.md](spec.md). Порядок фаз — от проверяемого ядра к окнам.

## Фаза 1. Ядро: проверка структуры (без GUI)

**Файлы:** `src/stanok/services/project_check.py` (новый), `tests/services/test_project_check.py`.

- `check_project_structure(folder, name, store) -> ProjectCheck`.
- Переиспользовать: `_scan_placeholders` (storage), `ExcelReader.read` и
  `_read_headers` (tables/excel), `detect_project_layout` (open_project_dialog —
  вынести в services, чтобы GUI его не импортировал из окна).
- Коды ошибок и предупреждений в `strings.py`, в `CheckIssue` хранится ключ и аргументы.
- Тесты: по одному на каждую строку таблицы 3.5, плюс позитивный случай.

**Готово:** тесты фазы зелёные; функция не импортирует Qt.

## Фаза 2. Ядро: подготовка папок

**Файлы:** `services/project_check.py` (или `services/project_setup.py`), тесты.

- `create_skeleton(base, name, store) -> Path`: проверка имени, создание
  `Данные`, `Шаблоны`, `Результат`, без конфига.
- `ensure_subfolders(folder) -> list[str]`: создать недостающие `Данные`/`Шаблоны`.
- `clone_structure(source_ref, base, name, store) -> Path`: копия `Шаблоны/` и
  `Данные/` источника, `Результат` пустой, конфиг не копируется.
- Тесты: имя занято, папка уже существует, копирование не трогает исходный проект.

**Готово:** функции покрыты тестами, GUI не нужен.

## Фаза 3. GUI: окна

**Файлы:** `gui/project_start_dialog.py` (окно 1: описание и три кнопки),
`gui/project_check_dialog.py` (подсказки, список ошибок, «Проверить» / «Закрыть»),
`gui/strings.py`.

- Список ошибок: `QTableWidget` с колонками «Файл», «Колонка», «Сообщение».
- Кнопка «Проверить» перезапускает проверку и обновляет список.
- Диалог «Создать» из `init_project` с `copy_files=False`.
- Тесты offscreen: кнопки вызывают нужные функции, список ошибок заполняется,
  повторная проверка после исправления.

**Готово:** сквозной путь «минимальный шаблон → положить файлы → Проверить → проект» проходит в тесте.

## Фаза 4. Подключение и уборка

- Кнопка создания в `main_window.py` открывает окно 1 вместо `CreateDialog` в режиме создания.
- Окно «Открыть проект» → «Выбрать папку» (022) использует `check_project_structure` для ветки «создать из папки».
- Удалить режим создания из `CreateDialog` (режим настроек остаётся).
- Обновить `docs/` (если есть описание потока создания), `CHANGELOG.md [Unreleased]`,
  `README.md` при упоминании шагов создания.
- Перенести спеку в Done в `specs/SUMMARY.md` с однострочным описанием.

**Готово:** `pytest tests/ -q` зелёный, в `specs/SUMMARY.md` запись в Done.

## Риски

- **Дублирование с 022.** Две ветки «выбрать папку» должны вести в одну проверку. Иначе расхождение неизбежно.
- **Дрейф порядка xlsx.** Источник по умолчанию — первый xlsx. Если порядок меняется в файловой системе, привязка меняется. Сортировать имена при сборе списка.
- **Большие xlsx.** Проверка читает заголовки и проверяет пустоту строк; полного чтения всех строк не нужно. Для проверки пустоты читать только первые несколько строк.
